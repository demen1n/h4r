# Применение урона к стеку (#68)

Как готовый урон превращается в погибших существ. Источник — `combat_creature.cpp`,
функции найдены по порядку линковки отладочного мапа между уже привязанными
соседями; декомпилят — `decomp/apply_damage.c` (не в git).

| функция | rva | что делает |
|---|---|---|
| `t_combat_creature::add_damage(int, t_combat_creature*, bool, bool, msg)` | `1f2800` | принимает удар в «ожидающий» урон |
| `t_combat_creature::resolve_damage()` | `1eee40` | ожидающий урон → раны и потери |
| `t_combat_creature::apply_damage(t_battlefield&, bool)` | `1ef2d0` | вызывает `resolve_damage`, при нуле существ запускает гибель |
| `t_combat_creature::kill(int)` | `1f3860` | убрать N существ без урона |
| `t_combat_creature::kill_permanently(int, msg)` | `1f38d0` | то же, со счётчиком безвозвратных |
| `t_combat_creature::resurrect(int, bool)` | `1f34a0` | лечение/воскрешение на N HP |
| `t_combat_creature::get_total_hits(bool, t_spell)` | `1f5350` | сколько HP осталось у стека |
| `t_combat_creature::blocks_movement()` | `1ef5a0` | `number > 0` |
| гибель стека (имя не привязано) | `1f4f70` | анимация, снятие эффектов, удаление |

## Поля

Смещения от начала `t_combat_creature`; `vb` — виртуальная база
(`t_abstract_combat_creature`), её смещение лежит в vbtable (`[this+0x9c]+8`).

| поле | смысл |
|---|---|
| `+0xb0` | `number` — существ в стеке |
| `vb+0xa0` | `wounds` — урон, уже полученный верхним существом |
| `+0x9c0` | ожидающий урон (`new_damage`; в подобъекте `t_attackable_object` это `+0xc`) |
| `+0xafc` | флаг «этот урон убивает безвозвратно» (4-й аргумент `add_damage`) |
| `+0xb8` | безвозвратные потери |
| `+0xa68` | сколько погибло при последнем применении |
| `+0xa6c` | счётчик «поглотить следующий удар» (эффект 0xbf) |
| `+0x194`/`+0x198`, `+0x404`/`+0x408` | щиты эффектов 0x10 и 0x44: флаг и запас |

Игра **не хранит HP верхнего существа**. Она хранит раны: `0 ≤ wounds < hp`,
остаток стека — `number · hp − wounds`. Пока максимум HP постоянен, это то же самое,
но при смене максимума (заклинания) сохраняются именно раны. Поэтому в `BattleState`
поле называется `wounds`, а HP верхнего существа — вычисляемое `top_hit_points()`.

Номера 0x10, 0x35, 0x44, 0x4f, 0x6a, 0x6f, 0xbf здесь — **эффекты** (`t_spell`, проверка
через vtable виртуальной базы, слот +8), а не способности существ (те — слот +0x68
vtable по `+0x98`). Имена эффектов по номерам не сверены.

## add_damage

1. `damage < 1` → вернуть 0, ничего не менять.
2. Счётчик `+0xa6c` > 0 → уменьшить, вернуть 0 (удар поглощён).
3. Запомнить флаг безвозвратности.
4. Если третий аргумент истинен — **удача цели**: бросок боевого RNG
   `(id атакующего, id цели, 0x1b) % 10`; меньше удачи → урон `·2/3` (не ниже 1);
   меньше `−удачи` → урон `+ урон/2`. Это материал для #66, здесь не реализовано.
5. Эффект 0x4f (мученик): часть урона уходит другому стеку.
6. `total = get_total_hits(0, −1)`; если `pending + damage > total`, то
   `damage = total − pending`; отрицательное → 0; `pending += damage`.
7. Эффект 0x6a на цели запускает ответное действие на атакующего.
8. Возвращается принятый урон (плюс ушедший мученику).

Реализованы шаги 1, 3, 6: `wounds::accept_damage`, `BattleState::add_damage`.

## resolve_damage

```
(яд 0x6f и щиты 0x10/0x44 сначала уменьшают ожидающий урон)
wounds += pending
killed = wounds / hp            // hp — виртуальный get_hit_points, +0x30
показать всплывающий текст (pending, killed), если что-то из них > 0
pending = 0
если killed == 0: флаг безвозвратности = 0, выход   // number и «погибло в прошлый раз» не трогаются
killed = min(killed, number)
wounds -= hp · killed
number -= killed
last_killed = killed
если флаг безвозвратности: permanent_deaths += killed
флаг = 0
если number < 1: number = 0, wounds = 0, clear_influence()
иначе если killed > 0 и на стеке эффект 0x35: его обработчик (5f4ad0)
```

Реализовано без яда, щитов и эффекта 0x35: `wounds::resolve_damage`,
`BattleState::apply_damage`.

## kill

`n = min(n, number)`; `last_killed = n`; `number −= n`; если стало 0 — `wounds = 0`,
иначе раны верхнего существа остаются. `wounds::kill`, `BattleState::kill`.

## resurrect (не реализовано, записано для заклинаний)

```
revived = (hp − wounds − 1 + amount) / hp
cap     = исходное число − permanent_deaths − number   (не меньше 0)
revived = clamp(revived, 0, cap)
heal    = min(amount − revived · hp, wounds)
wounds −= heal;  number += revived
```

То есть суммарные HP стека растут ровно на `amount`, пока есть кого поднимать;
безвозвратно погибшие не возвращаются.

## get_total_hits

`number · hp − wounds`, где `hp` — базовые HP с бонусами эффектов 0x33, 0x39, 0x72
(каждый `hp += (hp + 2) >> 2`) и 0x21 (`×2`); плюс запасы щитов 0x10 и 0x44. Аргумент
`t_spell` исключает один эффект из расчёта. У нас пока `count · hit_points − wounds`
без эффектов (`wounds::total_hits`).

## Гибель

`apply_damage` после `resolve_damage` проверяет `get_number() == 0` и вызывает `1f4f70`.
Разобрано только то, что нужно состоянию: `blocks_movement` — это `number > 0`, то есть
тело остаётся объектом поля, но клетки не блокирует. В `BattleState` погибший стек
сохраняет позицию, его занятость клеток становится неблокирующей; если он был
активным, ход завершается (наше решение, в exe не проверено). Снятие эффектов,
анимация, способности, реагирующие на смерть, — не разобраны.

## Сверка

`tools/testbench/apply_damage.py` исполняет в Unicorn настоящие `1eee40` и `1f3860`
целиком и блок ограничения `1f2a91..1f2ab8` из `add_damage`. Эффекты отсутствуют
(виртуальная проверка возвращает 0), форматирование текста, всплывающий текст,
обновление подписи и `clear_influence` заглушены; аргументы всплывающего текста
записываются. 1800 векторов (`R` 1642, `K` 81, `A` 77) лежат в
`crates/h4-rules/tests/apply_damage_vectors.tsv`, тест `apply_damage_vectors`
проверяет их без игры. Не покрыто: яд, щиты, удача, мученик, гибель.

Замечено по векторам: всплывающий текст показывает `wounds / hp` до ограничения
числом существ, а `clear_influence` вызывается и для стека, который уже был пуст.

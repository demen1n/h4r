# Урон в бою (heroes4.exe rus-3.0)

Сырой декомпилят: `damage.c`. Имена `t_combat_creature::*` перенесены с complete-3.0 (tier D, но
сигнатуры и `ret N` совпадают, поведение кода им соответствует). `FUN_*` — без имени; ниже
предполагаемые роли. Способности — `re/enum_creature_ability.tsv`.

## get_melee_damage(target, count = -1) — rva 1ee4d0

```
count = count < 0 ? creature.get_number() : count
base  = (damage_low + damage_high) * this->number / 2      // среднее × размер стека
dmg   = modify_damage(base, target, ranged=false, count)   // FUN_005edf30
return finalize_damage(number, target, dmg)                // FUN_005ee540
```

## get_ranged_damage(target, ...) — rva 1eebf0

Только при `has_ability(ranged)` и оставшихся выстрелах:
```
n    = shooters_alive(target)            // FUN_005ee400: учитывает уже полученный урон
base = (low + high) * n / 2
dmg  = modify_damage(base, target, ranged=true)
dmg /= max(1, range_penalty(target))     // FUN_00570800 -> t_abstract_creature::get_range_effect(дистанция до края)
return finalize_damage(n, target, dmg)
```

## Настоящий бросок — rva 1ee240 (имени нет)

`get_melee_damage` выше — это среднее (для ИИ и подсказки). Настоящий удар бросает кости
генератором боя (`decomp/random.md`, назначение 0, ключ — id цели и атакующего):
```
range = high - low + 1
if number < 10: sum = Σ по каждому существу (low + roll % range)
else:           sum = number * (10 бросков) / 10
return modify_damage(sum, target, ranged, moved, luck)
```
Рядом: rva 1ee380 — `modify_damage(high * number, ...)` (максимум), 1ee3c0 — `low * number` (минимум).
Слоты vftable атакующего (`this+0x98`, проверено по vftable `t_hero` и `t_combat_creature`):
`+0x20` high, `+0x24` low, `+0x28` get_defense_reduction(bool), `+0x30` hit points,
`+0x34` get_luck, `+0x44` get_offense(bool), `+0x68` has_ability.

## modify_damage — FUN_005edf30 (rva 1edf30)

Аргументы: base, target, ranged, moved (в melee по умолчанию слот `+0x18`), luck (0/1/2).
По дизассемблеру, по порядку:

1. **charging** (0x0b), только melee, moved > 500: `dmg = (moved*10/350 + 85) * dmg / 100`.
2. Если у цели слот `+0x40` истинен («великан»?): атакующий с 0x1c, или (ranged ? 0x35 : 0x2b)
   → `dmg *= 2`; иначе эффект заклинания 0x8c у атакующего → `dmg += dmg >> 1`.
   0x1c — `giantslayer`, 0x2b — `melee_giantslayer`, 0x35 — `ranged_giantslayer`.
3. **Удача**: множитель `m = {1.0, 1.25, 1.5, 2.0}[obj->[+0x60]]`, `obj = [this+0xa18]`
   (таблица double по VA 0x97cb68, rva 17b8f0). luck 1: `dmg = trunc(m * dmg)`,
   luck 2: `dmg = trunc(dmg / m)`.
4. `ratio = get_damage_modifier(...)`, `dmg = trunc(ratio * dmg)`.
5. Оберег по школе атакующего (слот `+4`: 0 life — способность 0x22 или эффект 0x77;
   1 order — 0x79; 2 death — эффект 0x76 или способность 0x10; 3 chaos — 0x75 или 0x0a;
   4 nature — 0x78; might — нет): `dmg = dmg * 100 / 150`.
6. fire_attack / breath_attack / arc_breath_attack (или large_area_effect при стрельбе)
   против fire_resistance: `dmg >>= 1`. cold_attack против cold_resistance: `dmg >>= 1`.
7. Не меньше 1.

## get_damage_modifier — rva 250a60 (подробно)

```
bonus = target.has_defense[+4](ranged)    // множитель защиты
red   = this[+0x28](ranged)               // get_defense_reduction
if red <= bonus: offense *= red
else if bonus > 1: bonus = 1
ratio = offense / (target.has_defense[+8](ranged) * bonus)   // +8 — базовая защита
clamp: сначала ratio < 0.05 (и NaN) → 0.05, потом ratio > 20 → 20
```

## finalize_damage — FUN_005ee540 (rva 1ee540)

cdecl: (attacker, number, target, already_dealt, dmg).
- Атакующий со способностью 0x42 (`stone_gaze`, взгляд медузы) против `t_combat_creature`
  (не 0x4d undead, не 0x2a mechanical, не 0x11 elemental): `x = (effectiveness_98 * target.vf90()) / 100` (если FUN_5b6140), и если
  `x * number >= 500` — `dmg += trunc(((x * number) * 0.001) * target.creature_hp)`.
  Важно: HP берутся у **цели** (`cast_target+0x98`, слот +0x30), не у атакующего.
  Полный разбор и границы сверки — в последнем разделе.
- `dmg = min(dmg, max(0, target.total_hp(+0x2c(1,-1)) - already_dealt))`.
- Цель с 0x07 (block): `dmg = (dmg * 7 + 5) / 10`.

## Что не хватает для полной картины

- Где решается удача атакующего (аргумент luck) и как настоящий удар собирает бросок,
  модификаторы и `finalize_damage` (`attack.cpp`).
- Игровые названия слота `+0x40` цели и эффекта 0x8c; поле `[+0x60]` для силы удачи.
- Структура `t_abstract_creature` (`+0x198`/`+0x408`/`+0x354` — что-то про полученный урон).
- Сверка с известными формулами сообщества (Equilibris `equilibris.chm`, `Skill_Guide.pdf`).

## Сверка с оригинальным машинным кодом (31 октября 2026)

`tools/testbench/compare.py` выполняет RVA `250a60` и `1ee540` в Unicorn:
320 случаев коэффициента и 144 случая финализации без способности 0x42.
Расхождений после исправления нет. У коэффициента знаменатель остаётся в x87
до деления (при CRT-настройке — 53 бита): прежнее округление `defense_basic * bonus` до f32 давало отличие
в один ULP на двух входах. В Rust для этих промежуточных действий используется
f64; минимальные случаи сохранены в `ratio_keeps_x87_intermediate_precision`.
Это проверка указанного корпуса, а не доказательство совпадения всех float-входов.
На первом шаге полная цепочка `modify_damage` и настоящие броски ещё не покрывались;
броски проверены следующим шагом ниже.

## Сверка бросков (31 октября 2026)

## Полная цепочка modify_damage (31 октября 2026)

Сверены 1321 случай RVA `1edf30`, включая вложенные `250a60`, `17b8f0`
и `__ftol` (`4ed234`). Виртуальные методы возвращают входные статы, способности
и эффекты; вычисления, таблица удачи, ветвления и округление — оригинальные.
Разгон проверен при moved 499/500/501/524/525/700/1400, melee/ranged;
все варианты giant slaying и эффект 0x8c; удача 0/1/2 × 4 силы; шесть школ,
обереги от эффектов и способностей (включая несколько источников одновременно);
огонь, дыхание, area только при стрельбе, холод и сочетания сопротивлений.
Дополнительно: 625 границ целочисленного результата и 128 смешанных случаев.

**Настройка x87:** в PE-точке входа `4f0a71` вызывается CRT init `4efd77`,
его указатель по VA `a8a564` ведёт в `4ed10b`, затем `4f2ee8` вызывает
`4f8e99(0x10000, 0x30000)` — выбор 53-битной точности. Стенд выполняет
`4f2ee8` перед проверками: из reset control word 0x037f получает 0x023f
(53 бита, округление к ближайшему, исключения замаскированы); проверяет
и сохраняет control word в отчёте. Первоначальное
состояние Unicorn нельзя считать соответствующим запуску игры.
Прямых вызовов этих функций управления точностью из игрового кода не найдено;
изменение точности сторонними DLL этим не исключается.

В `modify_damage` результат `250a60` не сохраняется в f32: сразу `fimul`
на урон, затем `__ftol`. Прежняя версия Rust теряла единицу урона, например
base=6/offense=5/defense=6 → 4 вместо 5. Теперь внутренний коэффициент — f64,
соответствующий 53-битной настройке CRT; публичный `damage_modifier` по-прежнему
возвращает f32. Из 1321 случая до исправления расходились 159, после — 0.
Ответы оригинала — `crates/h4-rules/tests/modifier_vectors.tsv`, минимальная
регрессия — `scaling_keeps_the_coefficient_at_crt_precision`.

Общий прогон стенда: 1857 запросов, 0 расхождений, включая прежние RNG и кости.
На этом шаге ещё не были закрыты способность 0x42 и численная цепочка атаки;
они разобраны следующим шагом ниже. Настоящие объекты поля боя пока не подключены.

## Способность 0x42 и численная атака (31 октября 2026)

Восстановлены `finalize_attack_damage`, `Ability42Target`, `HitOptions`,
`attack_hit`. Простая `finalize_damage` оставлена как применение последних
ограничений; `melee_hit` делегирует общей цепочке без входов эффектов.
Бой-заглушка использует `attack_hit` и для melee, и для ranged, по-прежнему
без способностей/магии: источник этих игровых свойств пока не подключён.

Алгоритм финализации по дизассемблеру RVA `1ee540`:

1. Атакующий имеет 0x42 (`stone_gaze`); цель не имеет 0x4d undead / 0x2a mechanical /
   0x11 elemental. Имена — из таблицы ключевых слов exe (VA `0xa64160`, пары
   `{i32 значение; char* имя}`; прежний `re/enum_creature_ability.tsv` читал её со
   сдвигом и подписывал 0x42 как stealth, 0x2a как magic_immunity). Эффект 0x98 в таблице
   заклинаний (VA `0x994f80`) — тоже `stone_gaze`; исключения совпадают с подсказкой
   медузы в `table.creatures` («не действует на нежить, механизмы и элементалей»).
   Имена `Ability42Target`, `HitOptions::ability_42` и запрос стенда `ability42`
   пока оставлены численными.
2. dynamic_cast цели к `t_combat_creature` успешен; effect 0x98 разрешён
   проверкой `1b6140` (это обёртка большой системы допустимости заклинаний).
3. `1f1de0` даёт эффективность; слот +0x90 объекта по `target+0xa4` — силу.
   Их 32-битное произведение делится на 100 с усечением. Если полученная
   сила × число атакующих меньше 500, бонуса нет.
4. На x87, в 53-битной точности и именно в таком порядке:
   `bonus = trunc(((double(power) * number) * 0.001) * target_creature_hp)`.
   Прибавить к модифицированному урону, ограничить оставшимися HP, затем block.

Стенд: **912** случаев способности: порог, усечение силы при сопротивлении,
разные HP цели, исключающие способности по отдельности и вместе, не-существо,
запрет эффекта, отсутствие 0x42, overkill, уже нанесённый урон и block.
**176** последовательностей численной атаки: исходный RNG, три удара через
`1ee240` (он сам вызывает настоящий `1edf30`) и `1ee540` на тех же входах
и объектах фикстуры; после трёх ударов сравнивается следующий бросок.
Есть melee/ranged, удача, разгон, оберег, сопротивления и 0x42 совместно,
границы размеров стека 9/10/11, малые и большие стеки, исключения цели.
Все ответы сохранены в `tests/attack_vectors.tsv`; работают в CI без exe.
Отдельный Rust-тест проверяет журнал: бонус → ограничение HP → block.
Общий стенд: **2945 запросов, 0 расхождений**.

**Граница проверки:** dynamic_cast и допустимость эффекта 0x98 — явные входы
фикстуры. Большая система `1b30a0` и её проверки иммунитетов/сторон/эффектов
не перенесена и не объявляется проверенной. Для `1f1de0` используется явная
запись эффекта 0x98 с флагом resisted (0x800000) и виртуальная величина
сопротивления; этот путь helper исполняет оригинальным кодом. Обход сопротивления
атакующими со способностями 0x52/0x1f здесь не задаётся. В API Rust передаётся
уже разрешённая эффективность, а не догадка о результатах системы заклинаний.

Связка двух функций в стенде — проверка численного урона, не исполнение всей
команды поля боя. Из вызывающего кода (`175ea0`, вызовы `175efe`/`175ffc`)
видно, что после бросков/модификаторов урон передаётся виртуальному обработчику
цели. Полный dispatch, дистанционные штрафы, выбор удачи, изменение HP/смерть,
ответный удар и прочие побочные эффекты настоящей атаки остаются работой этапа боя.

## Эффективность эффектов (продолжение 31 октября 2026)

`h4_rules::effects::Effectiveness` переносит ветвление RVA `1f1de0`.
Сначала запрет допустимости даёт 0. Флаг 0x800000 включает сопротивление
независимо от сторон; без него 0x1000000 включает его только между разными
сторонами. Иначе результат 100. Способность атакующего 0x52 даёт 100;
0x1f выбирает виртуальное сопротивление цели для id -1 вместо id эффекта.
Результат — 100 минус сопротивление, без ограничения диапазона, с i32 wrapping.
Сравнение сторон подтверждено дизассемблером: декомпилят теряет результат
первого виртуального вызова. В фикстуре стороны представлены байтовыми id.

320 случаев оригинальной функции: все комбинации шести булевых условий,
разные общее/частное сопротивления, отрицательные и крайние i32.
0 расхождений; ответы сохранены в `tests/effectiveness_vectors.tsv`.
В стенде исполняются оригинальные проверки флагов и ветвление функции;
`1b6140`, запись эффекта и виртуальные аксессоры — границы фикстуры.
Это пока отдельный API: численная атака принимает прежнюю разрешённую эффективность.

Для эффекта 0x98 `1b6140` вызывает `1b30a0` с нулевым параметром диагностики.
Общий путь проверяет слот цели +0x40 / флаг 0x8000000, затем `1b3540`,
`1b3a10`, фильтр артефактов `40cb30` (кроме способности цели 0x3f),
`1b4770`, `1b5750`, `1b5a80` и, при наличии атакующего, `1b3cf0`.
Специальные ветки switch для других id к 0x98 не относятся.
Эти фильтры и сам расчёт виртуального сопротивления ещё не перенесены;
полный пункт допустимости в плане остаётся открытым.

## Фильтры иммунитетов и полного сопротивления (продолжение P1)

Перенесены четыре независимых фильтра в `h4_rules::effects`:

- `ImmunityFilters::allows_general` — RVA `1b3540`: способность 0x3f
  пропускает фильтр. Иначе запрещают способность 0x26, эффекты 0x89/0x03;
  флаг 0x8000 вместе с эффектом 0x28 или способностью 0x15;
  флаг 0x400 вместе с эффектом 0x14 или способностью 0x0d;
  флаг 0x4000 вместе со способностью 0x03.
- `allows_target_kind` — `1b3a10`: способность цели 0x3f либо флаг 0x200000
  со способностью атакующего 0x2d пропускают фильтр. Иначе цель с 0x2a
  требует флага 0x10, с 0x4d — флага 0x20, с 0x11 — флага 0x02.
- `allows_effect_98` — ветка 0x98 (и 0x0b) в `1b4770`: способность цели
  `blind` (0x05) запрещает эффект, кроме цели со `spell_vulnerability` (0x3f).
  Имена подтверждены таблицей ключевых слов exe, исправленной в main.
- `ResistanceGate::allows` — `1b5750`: при наличии атакующего не-враждебная
  цель пропускается; способность цели 0x3f также пропускает фильтр.
  Способность атакующего 0x52 пропускает его, если у цели нет 0x26.
  Затем сопротивление применяется при флагах 0x800000/0x2000 либо при
  0x1000000 с атакующим с другой стороны. Значение ≥100 запрещает эффект.
  При отсутствии атакующего флаг 0x1000000 сам по себе запрета не даёт.
  Здесь **нет** выбора общего сопротивления по 0x1f: этот выбор находится
  в другой функции, `1f1de0`, уже после допустимости.

Декомпилят теряет параметры cdecl и переносит их между переменными;
порядок аргументов и ветвление проверены дизассемблером. В фикстуре
виртуальный слот цели +0x7c возвращает заданное сопротивление, а слоты
способностей и эффектов читают массивы входных id. `1b5750` исполняет
настоящий `is_hostile` (`00cd80`), проверку сторон и флагов.
Функции фильтров и `464ec0` исполняются оригинальным машинным кодом;
заглушки готового результата допустимости для этих четырёх функций нет.

Корпус `--only immunity`: 7088 сценариев, каждый возвращает четыре результата
(28 352 отдельных ответа). Включены все 512 подмножеств девяти проверяемых
способностей цели на двух наборах флагов с/без 0x2d; отдельные флаги и
эффекты; отсутствующий атакующий; 0x52 против 0x26/0x3f; враждебность и
равенство сторон по отдельности; сопротивление -1/0/99/100/101/i32::MAX.
Все совпали. Ответы сохранены в `tests/immunity_vectors.tsv` и проверяются
обычным `cargo test`, без exe или игровых данных.

**Оставшаяся граница:** эти четыре функции не заменяют весь `1b30a0`.
Не перенесены его начальная проверка цели, фильтр артефактов `00cb30`,
фильтр сторон/эффекта атакующего 0x90 (`1b3cf0`), повторное наложение
эффекта (`1b5a80`), загрузка настоящей записи 0x98 и вычисление виртуального
сопротивления. Они также не подключены к бою-заглушке. Полный пункт P1
остаётся открытым; способность 0x3f не означает обход всех оставшихся фильтров.

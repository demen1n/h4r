# Расстановка препятствий на поле боя (`t_combat_obstacle_placer`)

Исходник оригинала — `combat_obstacle_placer.cpp`. Адреса — RVA русского exe 3.0 (Бука).
Порт — `h4-rules/src/obstacle_placement.rs` (`place_obstacles`).
Сверка с оригиналом — `tools/testbench/obstacle_placer.py` (см. в конце).

## Где вызывается

`1615a0` (подготовка поля боя) идёт в таком порядке:

1. `initialize_cell_map` / `initialize_cell_vertex_map` — земля поля из карты приключений
   (генератор начальной земли **не портирован**);
2. при осаде — части замка (`162400`), `battlefield+100` = дальний ряд замка;
3. `162aa0` — наложение пресета (`decomp/battlefield.md`);
4. `162cb0` — блокировка краёв: первая и последняя клетка каждого ряда и все клетки
   с x + y < 55 (верхний угол ромба) получают бит `0x04`
   (`BattlefieldGrid::block_edges`);
5. конструктор расстановщика `208ec0(battlefield, осада, battlefield+100)` и `execute` (`20a270`).

## Алгоритм `execute` (20a270)

1. **`clear_start_positions`** (`209190`). Таблица стартовых слотов армий заполняется
   статическим инициализатором `224270` (VA `0xaaf1e0`, по 7 точек на сторону, 14 int):

   | сторона | слоты (x, y) | герой |
   | --- | --- | --- |
   | 0 | (76,51) (85,55) (76,60) (85,64) (76,69) (85,73) (76,78) | (91,64), VA `0xaaf2f0` |
   | 1 | (33,32) (24,37) (33,41) (24,46) (33,50) (24,55) (33,59) | (18,46), VA `0xaaf328` |

   Для каждой стороны (в осаде сторона 1, защитники в замке, пропускается):
   прямоугольник A = от слота 0 −3 до слота 6 +4, B = от слота 1 −3 до слота 5 +4
   (полуинтервалы); если B.x0 > A.x0, A и B меняются; затем «лесенка» шириной в одну
   клетку от `B.x1 − 1` до `A.x0` включительно, y-концы сдвигаются на знак разности
   на каждом шаге; квадрат 7×7 вокруг героя. В осаде ещё 7×7 от (замок, ворота.y).
   «Очистить» (`clear_rect`, `209040`) = запретить там блокирующие препятствия;
   оригинал заодно удаляет уже стоящие объекты с блокировкой и типом < `0x22`
   (бывают только в осаде) — в порте этого нет.
2. Контекст боя (`battlefield+0xc0` → `10c610` → `+0x20`) — флаг моста. **Не на мосту:**
   **`cut_paths`** (`209710`): два прохода шириной 4 и один шириной 7.
   Проход (`209650`): от (76, y₁) до (33, y₂), y₁ — бросок назначения `0x1f`
   в [51, 78], y₂ — `0x20` в [32, 59]; в осаде конец — (замок + 4, y₂), а широкий
   проход идёт от (76, `0x21`) к (замок + 3, ворота.y + 3).
   Прокладка (`2093f0`): список целей, работаем с последней. Если цель дальше одной
   клетки — середина половинного шага (`dx/2`, `dy/2`, деление к нулю) сдвигается
   поперёк на `shift = r % (2k+1) − k`, где `len = ⌊√(hx²+hy²)⌋` (x87 + `__ftol`),
   `k = len/2`, `r` — бросок `0x1e` (если k = 0, сдвига нет);
   новая точка `(hx − hy·shift/len, hy + hx·shift/len)` добавляется в список. Если цель
   рядом — очистить квадрат `width` с центром в текущей точке (`(width−1)/2` влево),
   перейти в цель, убрать её из списка.
3. **Обход в ширину**: очередь начинается с первой клетки последнего ряда.
   Для каждой клетки **`examine`** (`209fa0`):
   - бросок `0x23` по (x, y): `r % 1000 < плотность` и клетка разрешена →
     для **всех** моделей кэша заголовков (в порядке файла) вес `get_weight`;
     модели с весом > 0 — кандидаты; число кандидатов по типам; вес умножается на
     (наибольшее число по типам) / (число своего типа), не меньше 1 — каждый тип
     получает равный шанс независимо от числа моделей; бросок `0x22` по (x, y)
     `% сумма`; идём по списку, вычитая веса, до `< 1` (так что r, равный первому
     весу, ещё выбирает первую модель) → **`place`**;
   - иначе (не выпало, нет кандидатов) — в очередь соседи радиусом 1.
4. **Не на мосту:** `t_combat_obstruction_finder` (`20b480`, `20ba60`, `20bc10`,
   `20bcf0`) ищет участки, отрезанные препятствиями, и прорубает к ним пути
   (`clear_rect` вдоль пути по 7×7). **Не портировано** — нужен боевой поиск пути.

Плотность клетки сначала 20 (2 %), у новых препятствий 200 (20 %) — получаются группы.

### `get_weight` (209900)

Модель ставится центром в точку: верхний левый угол `p − (w−1)/2`, `(h−1)/2`.
Для каждой клетки футпринта, по x внешним циклом:

- вне поля → 0; модель блокирует, а клетка запрещена → 0;
- земля клетки (`& 0x1f`) = 9 → 0; нет бита `0x10` → 0 (так что `0x10` — «здесь можно
  ставить препятствия»: код пресета 1 ставит его не на мосту, 2 и 255 снимают);
- `battlefield+0x36c` ≠ 0 → земля считается водой (смысл флага не найден);
- осада и x < замок → 0;
- вес земли типа (`table[тип][колонка земли]`, колонка из `484a10`: река → вода,
  лава → вулкан, лёд → снег, магические земли → трава или вулкан) < 1 → 0;
- сумма (начинается с 5) += «соседство» + «наложение» клетки для этого типа;
  сумма < −4999 → 0.

Результат = сумма × наименьший вес земли (начинается со 100). У модели нулевого размера
цикл пуст, вес = 500.

### `place` (209b40)

Объект создаётся в (x0·16, y0·16) субклеток (`1772e0`). В очередь — клетки футпринта
+2 вокруг. Клетки футпринта получают строку «наложение» типа (по каждому типу-кандидату),
клетки футпринта +3 вокруг — строку «соседство». Плотность 200 — в квадрате футпринт ±
`(w + h − 2) / 3`, если это ≥ 1.

## Данные

- **`table.combat_obstacles`** — берётся из `updates.h4r` (порядок загрузки):
  в `text.h4r` другая версия (три болотные строки). Парсер `2089a0`: строка 0 — имена
  столбцов (типы препятствий), дальше строки: ячейка 0 — раздел (`terrain`/`adjacent`/
  `overlap`, `_stricmp`; пустая — продолжить предыдущий), ячейка 1 — земля (список
  из 19 имён, `_stricmp`) или тип (карта ключевых слов, `_strnicmp` с равной длиной),
  остальные — частоты (`never rare seldom common usually` = 0..4, та же карта).
  Значения: земля `[0, 5, 10, 20, 30]` (VA `0x982ab8`), соседство
  `[−5000, 0, 10, 30, 100]` (`0x982acc`), наложение `[−5000, 0, 10, 30, 30]` (`0x982ae0`).
  В памяти — 38 строк по 85 int (VA `0xaa7a38`): 9 земель, 38 соседств, 38 наложений.
  Незнакомые имена пропускаются молча. В установленной таблице опечатки:
  столбец `snow logs` (тип `snow_log`) и `fungal tree` не совпадают ни с чем,
  строки `burnt logs`, `swamp logs`, `swamp shrubs` — тоже. Поэтому **`snow_log`
  в оригинале никогда не ставится** (вес земли 0). Строка земли с именем не из 0..8
  (например, `river`) записала бы значение в область «соседства» — повторено.
  Ячейки читаются по номеру столбца без проверки длины строки (за концом — неопределённо;
  у нас пустая ячейка).
- **`combat_header_table_cache.combat_header.h4d`** — `CombatHeaderTable` (`1ff240`):
  5 u32 (3, 1, 2002, 10, 45; смысл неизвестен), u32 число (838), записи: u32-строка имени
  модели (без `combat_object.`) и заголовок `combat_object` без картинки. Тип в кэше уже
  разрешён по имени (`CombatObjectHeader::resolved_type`, см. `decomp/combat_object.md`).
- **enum `t_obstacle_type`** — карта ключевых слов VA `0x98d960` (пары значение/имя), 38
  типов: обычные 0..0x21, `castle_gate` 0x22, `castle_tower` 0x23, `castle_wall` 0x24,
  `special` 0x25 (`OBSTACLE_TYPE_NAMES`).

## Случайность

Все броски — боевой генератор (`decomp/random.md`), назначения ≥ 30, поэтому модуль id = 200
и результат не зависит от `battlefield+0x438`:

| назначение | аргументы | что |
| --- | --- | --- |
| `0x1e` | 0, 0 | сдвиг середины прохода |
| `0x1f`, `0x20` | 0, 0 | начало и конец прохода |
| `0x21` | 0, 0 | начало прохода к воротам (осада) |
| `0x22` | x, y | выбор модели |
| `0x23` | x, y | «ставить ли здесь» |

## Сверка с оригиналом

`tools/testbench/obstacle_placer.py` исполняет в Unicorn: геометрию поля (`34db60`),
конструкторы клеток (`183560`), блокировку краёв (`162cb0`), парсер таблицы весов
(`2089a0`, с настоящими картами ключевых слов из статических инициализаторов `208600`,
`3c8aa0`), конструктор и `execute` расстановщика, боевой генератор. Подменены: выдача
кэша заголовков и таблицы (готовые данные), загрузка модели (размер и тип записи),
создание объекта (только запоминаем позицию), масштаб картинки (1.0), профилировщик,
`atexit`, критические секции; финальный поиск отрезанных участков пропускается.

- синтетические входы (`examples/support/obstacle_case.rs`: 60 моделей, таблица с разным
  регистром, дублем столбца, незнакомыми словами, строкой `River`, пустыми ячейками;
  24 поля: однородные, пятна с реками, дыры без `0x10`, «мост», лишние биты, полосы;
  мост и «всё вода»): веса 3230/3230, **3107 препятствий в 24 сценариях совпали**;
  ответы — `h4-rules/tests/obstacle_placer_vectors.tsv`, проверяются в CI;
- установленные данные (838 моделей, настоящая таблица): веса совпали, 2608 препятствий
  в 24 сценариях совпали (не сохраняется: зависит от данных игры).

Не проверено: осада (ворота, замок, удаление объектов в `clear_rect`), финальный проход
`t_combat_obstruction_finder`, земля настоящего боя, вид на экране.

# adv_object: модели объектов карты

Код: `crates/h4-formats/src/adv_object.rs`, проверка — `examples/check_adv_objects.rs`
(все 2487 файлов без алиасов во всех архивах, 0 ошибок, чтение ровно до конца).
Декомпилят — `adv_object_read.c`.

## Цепочка чтения (rva русского 3.0)

- `4f260` `t_conversion_cache_data<t_adv_object_model_24,…>::do_read` → `4d190` (свободная
  `read(streambuf, t_adv_object_model_24&)`): u16 версия, затем
- `4c860` `t_adv_object_model_base_base::read(stream, version)`: версии 1..6, футпринт,
  тип (`65960`), режим «плоских» клеток, флаг;
- `4c470`: u8 вид картинки (0 overlay, 1 underlay) → `3cdda0` (overlay, u16 версия < 3) или
  `t_underlay_adv_object_image_24::read`;
- `444620` / `444740` (`t_simple_adv_object_image_24`) → `349930` (`t_image_sequence::read`,
  в мапе имя `duplicate_shadow` ошибочно) → `349a90` → `18dfd0` (группа слоёв) и
  `595570` (слой);
- `3cc840`: u32 n + n×i16 — глубины столбцов overlay.

Наборы битов: `4cff0` — `(n+7)/8` байт, младший бит первый.

## Что подтверждено

- Индекс клетки — `y * width + x` (`is_cell_flat`, `4c6f0`).
- Поле `+0x1c` (u8 после типа, ≤ 2) — режим плоских клеток: 0 — нет, 1 — плоские
  непроходимые клетки, 2 — все (`is_cell_flat`, `are_any_cells_flat`). Для версий < 4
  вычисляется: 1, если объект больше 1×1.
- Кромки-триггеры: `is_trigger_cell` (`4c790`) — клетка срабатывает, если одна из её четырёх
  кромок помечена и кромка на краю футпринта или клетка непроходима. «Левые» кромки
  `w × (h+1)`, индекс `x + w*y`; «правые» `(w+1) × h`, индекс `y + h*x`.
- Без кромок (флаг 0) в файле лежит массив `w × h`, но игра его выбрасывает
  (старый формат).
- Высоты вершин `(w+1)×(h+1)` байт (`get_vertex_height`, `4d160`). Блокировка кромок
  `2·w·(h+1)` и `2·(w+1)·h` бит — назначение по именам `is_left/right_edge_blocked`.
- Тип объекта: u16 0, три пары (u16 id, строка); игра ищет сначала по имени.
- Анимация: в `t_image_sequence` версии 3 три u16 (режим, base frame, base shadow), но
  `3490c0` пересчитывает их по именам слоёв: `base frame`/`base shadow` — неподвижная часть,
  под каждым кадром. Версия 1 после смещения хранит ещё строку.

## Что найдено проверкой на данных (не по коду)

- Число столбцов глубины = столбцы по 32 px, покрывающие кадры без теней в координатах
  «после смещения»: совпало у всех 2259 overlay.
- Точка привязки (координаты слоя + смещение = 0,0) — верхний угол первой клетки футпринта:
  у 1×1 картинка по центру и низ около y = 32; у 3×3 бока около ±96, низ около 96.
- Ось x футпринта идёт на экране вниз-влево (в `h4-game` это `row`), y — вниз-вправо (`col`):
  у объектов N×1 картинка уходит влево, пары `Sawmill` 2×3 / `Sawmill R` 3×2 на скриншоте
  стоят правильно.
- Глубина столбца обычно = −(cx+cy+1) передней клетки футпринта под столбцом (1746 из 2259);
  остальные, похоже, подправлены художниками (у плоских 9×9 декалей все 0).

## Не проверено

- Как именно игра сравнивает глубину столбца с героями (знак, единицы, позиция объекта на
  карте): в прототипе ключ = y привязки − 16·глубина, герой при равенстве — спереди.
- Смысл флага `has_flag`/смещения флага (есть у жилищ, шахт) — по имени `get_flag_offset`.
- Финальный u16 в файлах `actor_sequence` (не в объектах) по-прежнему не объяснён.

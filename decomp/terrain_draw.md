# Отрисовка земли на карте приключений

Источник: декомпилят нашего `heroes4.exe` (сырой вывод — `terrain_draw.c`), проверка на данных всех 106 карт. Код у нас — `TerrainView::build_map` (`crates/h4-game/src/terrain_view.rs`), таблица наборов — `MAP_MASK_SETS` (`crates/h4-formats/src/transition.rs`).

## Номер набора масок (`mask_set`)

Загрузчик масок `FUN_008c6010` (rva `4c6010`) проходит по таблице из 20 указателей на имена (rva `6877a0`) и для каждого номера копирует весь вектор масок набора с этим именем в слот `0xad26a0 + 0x20·n`. Доступ — `t_transition_set_group::operator[]` (rva `4c62d0`).

| номера | набор |
|---|---|
| 0, 1 / 2, 3 / 4 | `water_to_land 1` / `2` / `3` |
| 5, 6 / 7, 8 / 9 | `land_to_water 1` / `2` / `3` |
| 10, 11 / 12, 13, 14 | `road 1` / `road 2` |
| 15 / 16, 17 / 18, 19 | `land 1` / `2` / `3` |

По пять номеров на вид границы: редактор, видимо, выбирает вариант случайно, а номера неравномерно отображаются на 2–3 набора. Наборы `water 1–2` и `river 1–2` в таблице не встречаются (на приключенческой карте не используются; возможно, нужны полю боя — не проверено).

## Номер маски (`id`)

`id` — индекс в векторе масок набора, то есть в порядке файла `transition.Transitions` (отрисовщик берёт `vector[id]`, запись 12 байт: глубина на +4, данные на +8). Проверка на картах: код маски по этому индексу всегда оказывается частью кода, посчитанного по соседям (`corner_code`): например, у соседей 2310, а в тайле две маски 2300 и 10. Поэтому переходов на тайл бывает до 6: редактор раскладывает угловой код на маски, которые есть в наборе.

## Земля: `FUN_0078a750` (rva `38a750`)

В памяти переход — u32: биты 0–4 terrain, бит 5 subtype, 6–14 id, 15–19 mask_set (в файле те же поля отдельными байтами). Для каждого перехода по порядку:

- Если земля рисуется метатайлами (флаг в таблице rva `57d224`: у всех, кроме special_all/life/order), берутся все метатайлы, накрывающие клетку. С 4-битной маской и больше чем одним метатайлом игра сначала собирает их в одну картинку тайла, потом смешивает её через маску (иначе полупрозрачные края смешались бы дважды). С 1-битной маской каждый кусок рисуется через маску сразу; результат тот же.
- Если не метатайлами (magic all/life/order — у них один файл без `.1/.2`), берётся одна картинка: карта делится на блоки 4×4, клетка берёт тайл `(x mod 4 + 3, y mod 4 + 3)` из картинки 10×10 (`FUN_0078b0d0`, rva `38b0d0`).

Своя земля клетки рисуется до переходов.

## Дороги: `FUN_0078aad0` (rva `38aad0`)

Переход дороги в памяти — u16: биты 0–1 road, 2–10 id, 11–15 mask_set. Тип дороги клетки — биты 6–7 слова тайла.

- **На клетке нет дороги:** каждый переход рисует дорогу своего типа через маску (так соседняя дорога заходит на край клетки).
- **На клетке есть дорога, переходов нет:** дорога рисуется целиком.
- **Есть дорога и переходы:** своя дорога собирается в буфер. Столбцовая маска сначала «всё видно», каждый переход с road 0 вычитает свою маску (`*mask &= ~column_bits`), то есть вырезает край там, где дорога кончается. Переходы с другим типом дороги рисуют ту дорогу в буфер через маску. Готовый буфер выводится через столбцовую маску (`FUN_0070e5c0`).

## Текстуры

Имена — из статических таблиц кэша метатайлов (rva `397b70`, строки около `673ae0`):

| terrain | файлы |
|---|---|
| 0–8 water, grass, rough, swamp, volcanic, snow, sand, dirt, subterranean | `terrain.<имя>.<subtype+1>.<1\|2>` (volcanic → `lava`) |
| 9 river, 10 lava, 11 ice | `terrain.river.water\|lava\|ice.<1\|2>` |
| 12 special_all, 13 life, 14 order | `terrain.magic.all\|life\|order` (одна картинка) |
| 15 death, 16 chaos, 17 nature | `terrain.magic.death\|chaos\|nature.<1\|2>` |
| 18 special_combat | `terrain.special.personal_combat.<1\|2>` — сопоставление по порядку строк, не проверено |

Дороги: массив текстур (rva `58ca68`) идёт парами по типу: 1 — `road.gravel`, 2 — `road.dirt`, 3 — `road.cobblestone` (кэши в порядке инициализации).

## Как игра кладёт метатайлы

`FUN_0078b0d0`/`FUN_0078b220` берут `t_metatile_map::get_metatile_info` по клетке/4 и смещение из записи метатайла (+0xa4/+0xa8); индекс тайла в метатайле — `(x − 4·cx + 4 − off_x) + (y − 4·cy + 4 − off_y)·10`. Значит, в игре метатайлы привязаны к сетке 4×4 с собственным смещением каждого, а список накрывающих клетку метатайлов даёт `FUN_007961a0`. У нас по-прежнему своё правило «каждые 5 клеток, шахматкой» (найдено экспериментом, выглядит без швов); перейти на игровое можно, когда станет понятно, откуда берутся смещения (в карте их нет; видимо, считаются при загрузке).

## Не разобрано

- `rock_terrain` / `rock_transition` тайла не используются.
- Откуда смещения метатайлов и выбор варианта (`.1`/`.2`) в `t_metatile_map`.
- Порядок осей: какая координата точки карты x, а какая y. У нас ряд → строка метатайла; на однородных магических землях ошибка не видна.

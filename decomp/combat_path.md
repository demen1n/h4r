# Поиск пути на поле боя (#62) — разведка

Класс `t_combat_path_finder` (RTTI). Всё ниже — по дизассемблеру и декомпилятору, **не выполнялось**;
порта пока нет. Адреса — rva в поддерживаемом exe.

## Что где лежит

| rva | что |
|---|---|
| `20c2f0` | конструктор: поиск для существа (`+0x4c`), флаги `+0x50` («летает»: способность `0x4a`) и `+0x51` (аргумент) |
| `20e250` | общая часть конструктора: карта клеток по сетке боя (по 28 байт на клетку), очередь |
| vtable VA `0x982bbc` | один слот: **сам поиск** `20d200` (~0x880 байт; Ghidra не выделяет его как функцию — `tools/ghidra/Decompile.java` теперь создаёт функцию по адресу) |
| `20e550` | положить точку в очередь (двоичная куча по стоимости, элемент 36 байт = запись клетки 28 байт + её ряд/столбец); кладётся, только если клетка ещё не взята или новая стоимость меньше |
| `20e7b0` | получить путь до клетки: запускает поиск (слот 0), затем идёт от цели по ссылкам «откуда пришли» (`+0x0c`, `+0x10` записи; пока ряд ≥ 0) и вставляет точки в начало вектора; `false`, если клетка не достигнута (бит 0 флагов) или путь пуст |
| `20e900` | карта блокировок: из существ поля (список `+0x44c`), объектов типов `0x23` и `0x24` и клеток поля с битом блокировки `0x04` расставляет флаги `1/3/4/9` в отдельную сетку |
| `20c7f0` (0x6fe) | подготовка перед поиском: блокировки, стартовая клетка, ёмкости (не прочитано) |
| `20e640` | после поиска: размечает достижимые клетки на футпринт существа (флаг `2` у клеток, куда существо встанет целиком) |
| `1f7680` | существо создаёт поиск лениво (по одному на значение флага) и держит в поле `+0x9f8`+`0x30` |
| `1772a0` | запись пути клетки поля: поиск текущего существа (`battlefield+0x28`), слот 0, затем запись `(ряд, столбец)` |

Родственный класс `t_combat_obstruction_finder` (`20b480`, поиск `20b4b0`) — «нет ли отрезанных участков»
для расстановщика препятствий; делит с этим классом очередь и карту клеток.

## Запись клетки (28 байт, по использованию)

`+0` u16 — цена входа (по местности), `+2` u16 — второй счётчик, `+4` u32 — стоимость пути до клетки,
`+8` u32 — флаги (бит 0 «достигнута», бит 1 «футпринт помещается», бит 2 «занята»,
`0x10` непроходима, `0x20`, `0x40`, `0x80`, биты 8–12 и 13–17 — подсостояние и направление),
`+0x0c/+0x10` — откуда пришли, `+0x14/+0x18` — собственные координаты.

## Основной цикл поиска (`20d200`)

Дейкстра: берёт из очереди клетку с наименьшей стоимостью и перебирает 8 соседей по таблице смещений
из статической инициализации (VA `0xaad80`..); стоимость шага — 100, у нечётных направлений (диагональ)
+50 %; для летающих и некоторых местностей другая; шаг не должен превышать предел (скорость, `iStack_134`);
есть вторая фаза с надбавкой +500 для клеток, где существо «упирается» (флаг `0x80`).
Остальное — не разобрано.

## Что делать дальше

1. Разобрать флаги клетки и цены шага до конца (по `20d200`, `20c7f0`).
2. Прогнать `20d200` целиком в Unicorn на случайных полях (вход: сетка клеток, блокировки, существо
   с фиксированными скоростью и способностями) и портировать в `h4-rules` с теми же векторами.
3. `get_path` (`20e7b0`) и куча (`20e550`) — отдельные маленькие куски, их можно портировать первыми.

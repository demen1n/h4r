Состояние:
- **перенесено и сверено** (выполнением в Unicorn, `tools/testbench/combat_path.py`, 500 карт,
  векторы `crates/h4-rules/tests/combat_path_vectors.tsv`): сам поиск `20d200` с кучей, разметка

## Запись клетки (28 байт)

| смещение | что |
|---|---|
| `+0` u16 | цена входа в клетку (земля; 100 на обычной) |
| `+2` u16 | движение, потраченное подряд над занятыми клетками (летун может пролетать, но должен уложиться в движение) |
| `+4` u32 | стоимость пути от старта |
| `+8` u32 | флаги, ниже |
| `+0x0c`, `+0x10` | откуда пришли (ряд, столбец); у старта (−1, −1) |
| `+0x14`, `+0x18` | «угол»: после поиска — сама клетка, после `20e640` — самый дешёвый угол футпринта, накрывающий её |

Флаги:

| бит | смысл |
|---|---|
| `0x01` | достигнута |
| `0x02` | покрыта: достигнута и не занята, или накрыта футпринтом такого угла |
| `0x04` | занята (существо, стена, закрытые ворота) |
| `0x10` | непроходима |
| `0x20` | башня (у объектов `castle_tower` без существа внутри) |
| `0x40` | линия стены/ворот (`castle_gate`, `castle_wall`) |
| `0x80` | два смысла: в фазе занятых клеток — «пройдена», со счётчиком в битах 8–12; у достигнутой — «шаг начат в пределах движения» |
| биты 8–12 | счётчик полушагов: 2 прямой, 3 диагональ |
| биты 13–17 | направление последнего шага |

Откуда флаги при подготовке (`20e0f0`, маска блокировки → флаг клетки): бит 4 → `0x20`, бит 1 → `0x04`,
бит 8 → `0x40`. Существа дают «занято»; `castle_wall` — «занято» и `0x40`; `castle_tower` без
защитника — `0x20`; `castle_gate` — «занято» и/или `0x40` в зависимости от состояния ворот и
существа (условия `577990`, `5778c0` не разобраны).

|---|---|---|
| 0 | northeast | (−1, 0) |
| 1 | east | (−1, 1) |
| 2 | southeast | (0, 1) |
| 3 | south | (1, 1) |

## Поиск `20d200`

Входы от существа: движение `M` (слот `+0x18` статов, со знаком), размер футпринта (слот `+8`),
способность `0x25 long_weapon` (`1ef5e0`: предел фазы занятых клеток 2·6 = 12 полушагов, иначе 2·2 = 4),
«летает» = нет эффекта 7 и (способность `0x19 flying` или эффект `0x2e`), эффект 9 — очередь
очищается (стоит на месте), флаг поиска `+0x50` — телепорт.

Цена пересечения стены для летуна: `(M − 200) / (размер + 1)`, не меньше 100; у телепорта — 100.

Если очередь пуста сразу — выход без разметки. Иначе, пока очередь не пуста: взять самую дешёвую
точку (копия записи + координаты); запись клетки **перечитывается из карты** (не из копии; одна клетка
может стоять в очереди несколько раз и раскрывается каждый раз). Если не телепорт — спросить у поля
направления зоны контроля (`172210`). Для каждого из 8 соседей в пределах рядов (`R` — раскрываемая,
`C` — соседняя, `d` — направление):

1. `C` непроходима — пропуск.
2. `R` не достигнута (фаза занятых клеток): пропуск, если `C` достигнута; счётчик `a = счётчик(R) + 2 + (d & 1)`,
   пропуск при `a > предел` или если у `C` есть `0x80` со счётчиком ≤ `a`; иначе `C.стоимость = R.стоимость + 500`,
   «откуда» = `R`, счётчик `a`, направление `d`, `0x80`; в очередь.
3. `R` достигнута:
   - пропуск, если `C` достигнута и `C.стоимость ≤ R.стоимость`;
   - `C` занята и существо не летает: пропуск, если `R.стоимость > M` (без знака) или у `C` есть `0x80`
     со счётчиком ≤ `2 + (d & 1)`; иначе `C.стоимость = R.стоимость + 500`, «откуда», направление,
     `0x80`, счётчик `2 + (d & 1)`; в очередь (начало фазы занятых клеток — так подходят к цели атаки);
   - иначе обычный шаг, цена:
     - из башни (`R` `0x20`): в башню — 0 (100, если `C` занята); наружу — 400 сразу со старта
       (`R.стоимость == 0`), иначе всё движение `M`;
     - пеший: цена входа `C` (`+0`);
     - летун/телепорт: стена (`C` `0x40`) в направлениях 0, 1, 7 — цена стены, иначе 100;
     - зона контроля в этом направлении: `+ M >> 2`;
     - диагональ: `+ цена >> 1`;
     - если `R` или `C` занята: «над занятыми» = `R.(+2) + цена`, пропуск, если больше `M` (со знаком); иначе 0;
     - итог `R.стоимость + цена`; пропуск, если `C` достигнута и итог ≥ `C.стоимость`;
     - записать: счётчик `2 + (d & 1)`, угол = сама `C`, `0x80` = (`M ≥ R.стоимость`, без знака),
       «над занятыми», «достигнута», «покрыта» = не занята, стоимость, «откуда», направление; в очередь.

Очередь — `std::vector` с кучей MSVC: вставка в конец и подъём, пока родитель **строго** дороже;
извлечение — `pop_heap` (`20c170`: дырка спускается к дешёвому потомку, при равенстве — к правому;
затем поднимается бывший последний), потом удаление последнего. От этого зависит, какой из равных
по стоимости путей выберется.

После очереди — `20e640` с футпринтом существа (круглая маска `1fc340` по размеру): для каждой
достигнутой незанятой клетки-угла (ряды с последнего к первому, столбцы по возрастанию) все клетки под
маской получают «покрыта» и угол — если раньше не были покрыты или новый угол дешевле прежнего
(сравнение со знаком). Границы exe не проверяет: подготовка не пускает поиск туда, где футпринт
выходит за поле (в стенде такие клетки помечены непроходимыми; порт пропускает клетки вне поля).

Путь `20e7b0`: если цель не достигнута — `false`; иначе от цели по «откуда», пока столбец «откуда» ≥ 0,
точки складываются **от цели к старту**, старт не входит; `false`, если путь пуст (цель — старт).

## Подготовка `20c7f0` (не перенесено)

1. Копия шаблонной карты поля для размера футпринта (кэш в поле `+0xe8`), `+0x48` из неё.
2. Объекты поля (список `+0x44c`), кроме самого существа: существа — «занято» (при флаге `+0x51`
   только враги без трусости и без эффекта 0x89 — уточнить); препятствия по типу: `castle_gate`,
   `castle_tower` (если в ней никого — `0x20`), `castle_wall` (см. таблицу флагов).
3. Старт: обычно `20e3f0` с позицией существа; в башне (байт существа `+0x9bc`) — `20c6d0`: клетки
   выхода вокруг башни ценой 400 (`20c400`, направление по `51ede0`).
4. Земля (`t_combat_terrain_map::refresh`): цена входа 100, 400 у клеток с `0x20`, у остальных — по
   маске типа земли из списка (болото, зыбучие пески и т. п.). При открытых для существа воротах они
   временно открываются (`5779c0`).

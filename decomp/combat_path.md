# Поиск пути на поле боя (#62)

Класс `t_combat_path_finder` (RTTI). Адреса — rva в поддерживаемом exe.

Состояние — **перенесено и сверено** выполнением в Unicorn:
- поиск `20d200` с кучей, разметка футпринта `20e640`, старт `20e3f0`, путь `20e7b0` —
  `h4_rules::battle::path` (`tools/testbench/combat_path.py`, 500 карт);
- шаблон поля для размера футпринта: карта блокировок `20e900` и шаблон `20dfd0` —
  `battle::path_template` (`combat_path_template.py`, 600 полей);
- подготовка для существа `20c7f0` (объекты, ворота, башни, старт в башне, цены входа) —
  `battle::path_prepare` (`combat_path_prepare.py`, 800 случаев и все направления `51ede0`
  для смещений −20..20).

Пока входы: карта земли боя и список цен существа (#182), зоны контроля `172210` (#63), смысл
двух запросов ворот и «стороны» существа (#74).

## Запись клетки (28 байт)

| смещение | что |
|---|---|
| `+0` u16 | цена входа в клетку (земля; 100 на обычной) |
| `+2` u16 | движение, потраченное подряд над занятыми клетками (летун может пролетать, но должен уложиться в движение) |
| `+4` u32 | стоимость пути от старта |
| `+8` u32 | флаги, ниже |
| `+0x0c`, `+0x10` | откуда пришли (ряд, столбец); у старта (−1, −1) |
| `+0x14`, `+0x18` | «угол»: после поиска — сама клетка, после `20e640` — самый дешёвый угол футпринта, накрывающий её |

Флаги:

| бит | смысл |
|---|---|
| `0x01` | достигнута |
| `0x02` | покрыта: достигнута и не занята, или накрыта футпринтом такого угла |
| `0x04` | занята (существо, стена, закрытые ворота) |
| `0x08` | под футпринтом клетка поля с флагом 0x04 (поиск не читает) |
| `0x10` | непроходима |
| `0x20` | башня |
| `0x40` | линия стены/ворот (`castle_gate`, `castle_wall`) |
| `0x80` | два смысла: в фазе занятых клеток — «пройдена», со счётчиком в битах 8–12; у достигнутой — «шаг начат в пределах движения» |
| биты 8–12 | счётчик полушагов: 2 прямой, 3 диагональ |
| биты 13–17 | направление последнего шага |

Откуда флаги — разделы «Шаблон поля» и «Подготовка» ниже. Флаг `0x08` (заблокированная клетка
поля под футпринтом) поиск не читает. `0x10` с `0x04` ставит шаблон там, где футпринт не помещается.

## Поиск `20d200`

Входы от существа: движение `M` (слот `+0x18` статов, со знаком), размер футпринта (слот `+8`),
способность `0x25 long_weapon` (`1ef5e0`: предел фазы занятых клеток 2·6 = 12 полушагов, иначе 2·2 = 4),
«летает» = нет эффекта 7 и (способность `0x19 flying` или эффект `0x2e`), эффект 9 — очередь
очищается (стоит на месте), флаг поиска `+0x50` — телепорт.

Цена пересечения стены для летуна: `(M − 200) / (размер + 1)`, не меньше 100; у телепорта — 100.

Если очередь пуста сразу — выход без разметки. Иначе, пока очередь не пуста: взять самую дешёвую
точку (копия записи + координаты); запись клетки **перечитывается из карты** (не из копии; одна клетка
может стоять в очереди несколько раз и раскрывается каждый раз). Если не телепорт — спросить у поля
направления зоны контроля (`172210`). Для каждого из 8 соседей в пределах рядов (`R` — раскрываемая,
`C` — соседняя, `d` — направление):

1. `C` непроходима — пропуск.
2. `R` не достигнута (фаза занятых клеток): пропуск, если `C` достигнута; счётчик `a = счётчик(R) + 2 + (d & 1)`,
   пропуск при `a > предел` или если у `C` есть `0x80` со счётчиком ≤ `a`; иначе `C.стоимость = R.стоимость + 500`,
   «откуда» = `R`, счётчик `a`, направление `d`, `0x80`; в очередь.
3. `R` достигнута:
   - пропуск, если `C` достигнута и `C.стоимость ≤ R.стоимость`;
   - `C` занята и существо не летает: пропуск, если `R.стоимость > M` (без знака) или у `C` есть `0x80`
     со счётчиком ≤ `2 + (d & 1)`; иначе `C.стоимость = R.стоимость + 500`, «откуда», направление,
     `0x80`, счётчик `2 + (d & 1)`; в очередь (начало фазы занятых клеток — так подходят к цели атаки);
   - иначе обычный шаг, цена:
     - из башни (`R` `0x20`): в башню — 0 (100, если `C` занята); наружу — 400 сразу со старта
       (`R.стоимость == 0`), иначе всё движение `M`;
     - пеший: цена входа `C` (`+0`);
     - летун/телепорт: стена (`C` `0x40`) в направлениях 0, 1, 7 — цена стены, иначе 100;
     - зона контроля в этом направлении: `+ M >> 2`;
     - диагональ: `+ цена >> 1`;
     - если `R` или `C` занята: «над занятыми» = `R.(+2) + цена`, пропуск, если больше `M` (со знаком); иначе 0;
     - итог `R.стоимость + цена`; пропуск, если `C` достигнута и итог ≥ `C.стоимость`;
     - записать: счётчик `2 + (d & 1)`, угол = сама `C`, `0x80` = (`M ≥ R.стоимость`, без знака),
       «над занятыми», «достигнута», «покрыта» = не занята, стоимость, «откуда», направление; в очередь.

Очередь — `std::vector` с кучей MSVC: вставка в конец и подъём, пока родитель **строго** дороже;
извлечение — `pop_heap` (`20c170`: дырка спускается к дешёвому потомку, при равенстве — к правому;
затем поднимается бывший последний), потом удаление последнего. От этого зависит, какой из равных
по стоимости путей выберется.

После очереди — `20e640` с футпринтом существа (круглая маска `1fc340` по размеру): для каждой
достигнутой незанятой клетки-угла (ряды с последнего к первому, столбцы по возрастанию) все клетки под
маской получают «покрыта» и угол — если раньше не были покрыты или новый угол дешевле прежнего
(сравнение со знаком). Границы exe не проверяет: подготовка не пускает поиск туда, где футпринт
выходит за поле (в стенде такие клетки помечены непроходимыми; порт пропускает клетки вне поля).

Путь `20e7b0`: если цель не достигнута — `false`; иначе от цели по «откуда», пока столбец «откуда» ≥ 0,
точки складываются **от цели к старту**, старт не входит; `false`, если путь пуст (цель — старт).

## Шаблон поля `10e4f0` → `20e900` → `20dfd0`

Поле держит по шаблону на размер футпринта (кэш `+0x1b8`); при промахе один раз строит карту
блокировок `+0x1a4` (`20e900`), затем шаблон.

Карта блокировок (u32 на клетку; смысл у 4 младших бит, остальные — из регистра с адресом поля):
1. объекты общего списка (`+0x44c`), у которых виртуальные `+0x10` и `+0x10` базы (`+8`) отвечают
   «да» (блокирует и закреплён — неподвижные декорации): круглая маска их размера в углу
   `позиция >> 4` (арифметический сдвиг) **присваивает** 1;
2. список частей замка (`+0x538`): `castle_tower` присваивает 4, `castle_wall` — 9 (1 | 8), прочие
   типы (ворота) — ничего; позже записанные затирают раньше;
3. клетки поля с флагом 0x04 (байт `+1`): `|= 3`.

Шаблон (`20dfd0`): все записи нулевые (стоимость 0, «откуда» и угол (0, 0)), размер в `+0x2c`.
Флаги клетки: если футпринт с углом здесь вылезает за поле (`1650d0`: для каждой строки маски
проверяются её первая и последняя клетки) — `0x10 | 0x04`; иначе OR блокировок под маской
(`20eb20`) переводится: бит 1 → `0x04`, 2 → `0x08`, 4 → `0x20`, 8 → `0x40`.

## Подготовка `20c7f0`

1. Копия шаблона размера существа; `+0x48` — этот размер.
2. Объекты списка поля (`+0x448`) по порядку; пропуск, если `+0x10` объекта «нет», `+0x10` базы
   «да» (уже в шаблоне) или это само существо. Что поставить (`20e0f0` метит **расширенный**
   футпринт, см. ниже):
   - `castle_gate`: «занято», если ворота не проходимы, и `0x40`, если не `177990`. Проходимы —
     в режиме `+0x51`, при `177990` или для «защитника» (виртуальный `+4` эффектов с 1) без
     `1778c0`;
   - `castle_tower`: существо в центре (`позиция >> 4 + размер >> 1`, `170d90`); нет — `0x20`;
     есть — `0x20` только в режиме `+0x51` и если оно не враг, трусость (`1f52f0`) или эффект 0x89,
     иначе ничего;
   - `castle_wall`: «занято» | `0x40`;
   - существо: «занято»; в режиме `+0x51` — только враг без трусости и без эффекта 0x89;
   - прочее: «занято»; в режиме `+0x51` — если виртуальный `+4` базы «нет».
3. Старт: обычно `20e3f0` (клетка `позиция >> 4`). Существо в башне (байт `+0x9bc`, башня —
   `1f60a0`): очередь очищается; своя клетка — достигнута, стоимость 0, «откуда» (−1, −1),
   флаги `(f | 3) & 0xffffffa3 | 0x23`, в очередь **не** ставится; два прохода `20c400` по сторонам
   башни (угол `(tx, ty)`, размер `ts`, размер существа `m`): прямоугольник
   `tx..tx−m+1+ts` × `ty−m..ty+1+ts` с шагом (1, ts+m), затем `tx−m..tx+1+ts` × `ty..ty−m+1+ts` с шагом
   (ts+m, 1); свободная клетка (нет `0x14`) — запись: цена входа 100, стоимость 400, флаги 3 и
   направление от клетки существа (`51ede0`), «откуда» — клетка существа; в очередь. Биты 8–12 и
   18+ этой записи (и 13+ у обычного старта) в exe — мусор неинициализированной локальной; стенд их
   отбрасывает.
4. Цены входа. Только пешему (не телепорт и не летун) строится список цен `225320`; ему же,
   если есть ворота, нет `177990`, «защитник» и ряд клетки меньше `+0x64` поля, ворота открываются
   (`1779c0`) на время обновления карты земли. Затем по всем клеткам: `0x20` → 400; иначе 100, а
   у незанятой с битами земли, пересекающимися со списком, — цена **последней** подходящей записи.

Расширенный футпринт (`1fc8e0` → `1fc460`, проверка `1fc810`): сторона `a + b − 1` (a — объект,
b — существо), смещения `(1−b)..a` по обеим осям; клетка смещения (dx, dy) помечена, если существо
с углом в `угол объекта + (dx, dy)` пересекается с объектом. Существо в башне метится футпринтом
башни.

Направление `51ede0(a, b)`: `угол = __ftol(atan2(b.y − a.y, −(b.x − a.x)) · (−180) / π)`, где
отрицание целочисленное (к самой клетке — 0, не 4); `r = (360 − угол) mod 360`;
`направление = ((2r + 45) / 90) & 7` — совпадает с таблицей направлений.

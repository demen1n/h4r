# Земля поля боя и цена шага по ней (#182)

Подготовка карты поиска пути (`20c7f0`, `decomp/combat_path.md`) даёт незанятой клетке цену
**последней** записи списка цен существа, чьи биты совпали с битами земли под футпринтом; иначе
100, башня — 400. Обе половины перенесены в `h4_rules::battle::terrain_costs` и выполнены в
Unicorn целиком (`tools/testbench/terrain_costs.py`: 1200 списков и 1200 футпринтов на поле
102×102, `h4-rules/tests/terrain_costs_vectors.rs`), всё совпало.

## Биты земли

Карта земли боя (`224e50`, по одной на размер футпринта, кэш поля `10e780`) хранит для каждого
угла OR битов клеток футпринта (`224f60`, маска футпринта `1fc590` = круглая маска `1fc340`,
клетки вне поля пропускаются). Клетка поля — 0x1c байт с `+0x88`: тип земли — младшие 5 бит
байта 0, флаги — байт 1:

- флаг `0x40` — тип считается 1 (трава), особые биты ниже не ставятся;
- иначе, если клетка не под тем существом, для которого обновляют карту
  (`t_battlefield_cell::get_creature`): тип 9 → бит 1; флаг `0x02` → бит `0x400`;
- флаг `0x01` (второй вид земли) → биты из таблицы `0x9841a0` (`0x400 << тип`, у воды 0),
  иначе из `0x984158` (`1 << тип`).

Таблицы — пары (индекс, биты) для типов 0–8; записи 9–18 заполняются через `484a10` из
таблиц, которые строятся при запуске (ключевые слова) — не перенесено, типы ≥ 9 у нас — ошибка.
Кто ставит флаги `0x02` и `0x40` и какая земля у клеток в настоящем бою — не найдено
(начальная земля боя не перенесена; стенды и `BattlefieldGrid::standard` дают тип 1).

Обновление `225260` (для существа: прямоугольник вокруг него шире на размер футпринта) и
`2252d0` (прямоугольник ворот) пересчитывают углы `224f60` с исключением клеток этого существа
(`225170`). Поэтому `BattleState::terrain_bits(угол, размер, Some(существо))` считает биты сразу
с исключением — для остальных углов исключение ничего не меняет.

## Список цен существа (`225320`)

Вектор пар (биты, цена), затем `std::sort` MSVC по цене:

1. эффект 0xb3 `terrain walk` — список пуст;
2. уровень навыка 0xf героя (`+0x14` статов: у героя — он сам, у существа — нет; затем
   виртуальный `+0x50(0xf)`), без героя −1;
3. движение `m` (`1ef750`, `decomp/move_points.md`): `m > 200` → (`0x400`, `m >> 1`);
   `m > 400` → (`0x200`, `m >> 2`);
4. если навык < 2 — для земли `t` = 1..8: цена `c` из `0x9841e4` (100, 125, 150, 125, 150, 150,
   100, 100: трава, неровная, болото, вулканическая, снег, песок, грязь, подземелье) и `c + 50`
   для второго вида; −25 обеим, если виртуальный `+0x64(t)` (родная земля: у существа —
   по фракции через таблицу `0x9845e8` или `2535d0`; у героя — `2535d0` или артефакт земли
   `325740`), ещё −25, если навык ≥ 0; в список — только цены > 100. Ветка «−50 при
   `0 < навык < 0`» недостижима.

Список не длиннее 15 (2 + 13: трава, грязь и подземелье дешевле 101), а `std::sort` до 16
элементов — только сортировка вставками (`225a40`); её и перенесли. В клетке цена хранится в
16 битах (`as_entry_costs`).

# Ответный выстрел (#172)

Источник — русский exe 3.0 (Бука), адреса — RVA. Прочитано по дизассемблеру
(`tools/disasm.py`), **в Unicorn не выполнялось**. Порт — `battle::melee::plan_ranged_attack`
(решение) и `battle::melee_command::ranged_attack` (команда на `BattleState`).

## Функции

| что делает | rva |
|---|---|
| начало дальней атаки (`this` — `t_battlefield`, аргумент — цель) | `1693d0` |
| выстрел в ответ (ответчик, по кому) | `168d00` |
| отложенный ответ после первого выстрела | `169ca0` |
| следующий выстрел (осталось выстрелов) | `169930` |
| один выстрел: анимация `168720` (списание выстрела), затем `175ea0` с `ranged = 1` | `168ae0` |

## Начало дальней атаки (`1693d0`)

```
n = attacks(ranged = true) атакующего        # 1f1d10, ограничено выстрелами
bf.+0x504 = цель
нет ответа, если: байт цели +0xa9 («уже отвечал»), нет способности ranged (0x33),
    на цели эффект 0x2f, выстрелов цели <= 0, счётчик цели в карте угроз (10d200) != 0
иначе:
    a_first = у атакующего ranged_first_strike (0x34)
    d_first = у цели       ranged_first_strike
    если цель не can_act (155ea0): a_first = 1; d_first = 0
    (линия выстрела 16fe00 от цели к атакующему считается, результат здесь не используется)
    a_first и не d_first -> «отложенный ответ», иначе -> «одновременный»
```

Это та же проверка, что `can_shoot` (`170780`) плюс флаг ответа; общая проверка ответа
`1f23c0` здесь не вызывается, поэтому у флага нет исключения `n < 2`, а эффекты
0xba/0x9a заменяет `can_act`. `first_strike_immunity` (0x18) не участвует. Собственный
`ranged_first_strike` цели только гасит такой же у атакующего: цель первой не стреляет.

- **нет ответа**: очередь <- `169930(n − 1)`; выстрел; анимация реакции цели.
- **одновременный**: очередь <- `169930(n − 1)`; выстрел атакующего (`175ea0`), сразу за
  ним `168d00(цель, атакующий)`. Потери применяются позже (урон ожидающий,
  `apply_damage.md`), поэтому оба броска идут по целым стекам — как при ближнем ответе.
- **отложенный**: очередь <- `169ca0`; выстрел атакующего.

## Отложенный ответ (`169ca0`)

```
n = attacks(ranged = true) атакующего − 1    # считается заново: выстрел уже списан
если у атакующего и у цели существ > 0:
    если цель не can_act: 169930(n)
    иначе: 168d00(цель, атакующий); очередь <- 169930(n)
```

Число выстрелов пересчитывается после списания первого: у стрелка с `shoots_twice` и
двумя выстрелами одновременный путь даёт два выстрела, отложенный — один.

## Выстрел в ответ (`168d00`)

```
выход, если у ответчика: +0xa9, нет 0x33, эффект 0x2f, выстрелов <= 0, угрозы != 0,
    не can_act
t = 16fe00(ответчик -> центр атакующего)   # то, во что упрётся линия; нет -> атакующий
ответчик.mark_retaliated(нет unlimited_retaliation 0x4e)   # 1f6b20
если 1faa30(ответчик): выстрел по площади в центр t (169130)
иначе: 168ae0(ответчик, t)
анимации реакции
```

Ответ — **один** выстрел, сколько бы выстрелов ни давал `shoots_twice`; он тратит
выстрел (`168720`) и бросает удачу того, в кого попал. Штраф дальности в `175ea0` делит
урон только при значении больше 1, так что ответчик, который «не может прицелиться»
(`170800` = 0), стреляет в полную силу.

## Следующие выстрелы (`169930`)

```
если n <= 0 или у атакующего нет существ: конец
если у цели нет существ: конец
очередь <- 169930(n − 1); выстрел по цели (без ответа)
```

## Не перенесено

- линия выстрела ответчика может упереться в другой объект — exe стреляет в него;
  у нас ответ всегда идёт в атакующего;
- стрелки по площади (`1faa30`, `begin_area_effect_attack`);
- карта угроз `10d200` — вход вызывающего (`RangedContext::target_threats`);
- проверка исполнением в Unicorn (#70).

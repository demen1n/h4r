# Боевые описания актёров (`combat_actor`)

Проверено 31 октября 2026 на установленной русской Буке 3.0 с дополнениями.
Результат: **158 видимых ресурсов, 151 версии 6 и 7 версии 5**, все читаются ровно
до конца. Число включает алиасы, героев, заклинания и снаряды, а не только существ.

## Источники и границы уверенности

- Читатель в локальном `heroes4.exe`: RVA `1deb50`. Найден по пути загрузки
  боевой модели (`1de2e0` → `1deb50`), порядок полей сверён с байтами ресурсов.
- Таблица имён действий: VA `a5eb40`, 16 пар `(id, указатель на имя)`;
  инициализация RVA `1d5c70`. `stand` преобразуется в `base_frame` (`1d5ce0`).
- После чтения оригинал вызывает `1de980` для пар `(15,14)` и `(11,10)`:
  `wait_and_base` из `wait`, `full_walk` из `walk`. Функция копирует частоту,
  обнуляет дополнительный параметр и заменяет имя действия в ссылках.
- Имена из перенесённого мапа — подсказки. Например, `1de400`, помеченный
  конструктором, по фактическому коду разрушает строки модели.
- Декомпилят оставлен в `/private/tmp`, в репозиторий добавлена только эта заметка.

## Формат версий 5 и 6

Все числа little-endian; строки — `u16 длина` и байты имени.

| Поле | Тип | Примечание |
| --- | --- | --- |
| Версия | u16 | 5 или 6 |
| Два свойства модели | u8 × 2 | Физический смысл ещё не подтверждён |
| Длины prewalk, walk, postwalk | u16 × 3 | Те же позиции базовой модели, что в `adv_actor` |
| Точки по направлениям | 8 × (i32, i32, i32) | Только v6; не считать экранными координатами без проверки |
| Число действий | u16 | |
| Имя действия | строка | На каждое действие |
| Частота кадров | u8 | На каждое действие |
| Дополнительный параметр | u8 | Смысл не подтверждён; не называть моментом удара без проверки |
| Ссылки на анимации | строка × 8 | ne, e, se, s, sw, w, nw, n; пустая строка допустима |
| Смещение модели | i32 × 2 | После всех действий |

В v5 точек нет: оригинал подставляет для каждого направления
`(property_0 / 2, property_0 / 2, property_1 / 2)` с целочисленным делением.
Ветки v0–v4 присутствуют в exe, но в текущих ресурсах не встретились;
Rust-читатель пока возвращает для них ошибку.

Идентификаторы действий по порядку: block, cast_spell, die, fidget, flinch,
melee, melee_down, melee_up, postwalk, prewalk, walk, full_walk, ranged,
base_frame, wait, wait_and_base.

## Ссылки и применение

Обычное имя `Griffin.combat.melee.e` разрешается как
`actor_sequence.Griffin.combat.melee.e.h4d`. Несколько направлений могут ссылаться
на одну последовательность, поэтому каталог боевого режима строится по
описанию модели, а не по последнему компоненту имени файла.

`full_walk` и `wait_and_base` — производные действия. Их ссылки не проверяются
как обычные файлы и не показываются в новом режиме просмотрщика. Составление
таких анимаций потребует отдельного изучения кеша боевых последовательностей.
Читатель сохраняет исходные записи без подмены содержимого файла.

Оставшиеся **47 отсутствующих ссылок** перечислены точно в тесте:

- `combat_actor.behemoth`: 7 ссылок `cast_spell` на `behemoth.combat.spellcast.*`;
- `combat_actor.smoke`: 8 ссылок `cast_spell` на `Smoke.Smoke00`;
- `combat_actor.test_hero`: 32 ссылки prewalk/postwalk/wait/walk.

Все остальные непустые обычные ссылки разрешаются, последовательности декодируются
и содержат кадры. Это проверяет структуру и связи, но не доказывает совпадение
момента удара, положения модели и скорости воспроизведения с живым боем оригинала.

## Проверка

```sh
cargo test -p h4-formats --test combat_actors
cargo run -p h4-formats --example check_combat_actors
cargo run -p h4-viewer --bin h4-viewer -- --combat
cargo run -p h4-viewer --bin h4-dump -- Griffin melee e /tmp/griffin.png --combat
```

Просмотрщик использует частоту из описания при выборе действия; `[` и `]`
по-прежнему меняют её вручную. Отсутствующие обычные ресурсы показываются как
ошибка загрузки, без скрытой подмены другой анимацией. Графическое окно с оригиналом
пока не сверено; PNG-выгрузка работает без окна.

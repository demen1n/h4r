# Боевые объекты (`combat_object`)

Проверено 31 октября 2026 по Буке 3.0. Читатель `206aa0` вызывает
`206690` для свойств и `349930` для изображения. Перенесённое имя `write`
неверно: виртуальный метод потока `+0x18` читает байты.

| Поле | Формат |
| --- | --- |
| Версия | u16, 0–2 |
| Два свойства модели | u8 × 2 в v2; один u8 в v0/v1, общий для обоих |
| Дополнительный параметр | u8 |
| Частота анимации | u8; оригинал вычисляет период как 1000 / значение |
| Флаг | u8, оригинал преобразует в bool |
| Дополнительные свойства | пять u8, только v1/v2 |
| Тип объекта | u16 id и строка с u16 длиной, только v1/v2 |
| Изображение | image sequence без внешнего u16 обёртки actor_sequence |

Смысл двух первых свойств, дополнительного параметра, флага и пяти байтов
ещё не подтверждён. Их нельзя пока использовать как правила блокировки клеток.
В v0 оригинал задаёт нулевые дополнительные свойства и тип 0x25.
В v1/v2 оригинал ограничивает id диапазоном 0–0x25 и разрешает имя типа
через таблицу; читатель сохраняет исходные id и имя, не выполняя это разрешение.

Встроенная последовательность начинается непосредственно с версии image sequence,
затем читается существующим общим кодом слоёв, кадров, теней и смещения.
Сама структура image sequence не менялась.

`cargo run -p h4-formats --example check_combat_objects`: **1048 видимых ресурсов**,
1042 v2, шесть v0, без остатка. v1 в установке не встретилась; её порядок полей
подтверждён ветвлением читателя и синтетическим тестом, но не настоящим ресурсом.
Интеграционный тест читает все объекты и декодирует все их слои.
Синтетический тест проверяет версии, смещение последовательности, все усечённые
префиксы, неизвестную версию и лишний хвост. Внешний вид с оригиналом не сверялся.

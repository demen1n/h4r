# Карты `.h4c`

Источник: декомпилят нашего `heroes4.exe` (rva ниже; сырой вывод — `h4c_header.c`, `h4c_map_tiles.c`), проверка на всех 106 картах установки (`cargo run --release --example check_maps`). Читатель — `crates/h4-formats/src/map.rs`.

## Файл

```
"H4CAMPAIGN"  u32 0x16 (версия файла)  u8 0 (не мультисценарий)  gzip-поток
```

У всех 106 карт gzip начинается со смещения 15. Мультисценарные файлы (кампании, `t_multi_scenario_campaign_file_header`, список `t_map_info`) не разбирались. `t_single_scenario_campaign_file_header::read` (rva `1a9120`) открывает поток через `t_inflate_filter` и читает только заголовок карты. Потом `t_adventure_map::read_from_map` (rva `d15c0`, в мапе имени нет, найдено по вызову читателя заголовка) читает тот же поток с начала целиком.

## Порядок в потоке (`read_from_map`)

1. Заголовок карты (rva `37a320`, `read(streambuf, t_map_header&, progress)` из `map_header.obj`).
2. `FUN_004cf730` — создаёт игроков по заголовку, поток не читает. Затем четыре списка глобальных событий, каждый — u16 число и события: timed (`cfd80`), triggerable (`cffe0`), continuous (`d0240`), placed (`d04f0`).
3. 12 списков наград обелисков (`7c65f0`, по цвету обелиска): u16 0, u8 флаг, u16, при флаге u16 число наград; награда (`7c70f0`) — u16 0, строка типа (`artifact`: артефакт + u32; `material`: u8 ресурс + u32 количество).
4. `d0820` — на каждого игрока заголовка: u8 цвет, u8 флаг (+u16), с v23 ещё u8. `d0a40` — разрешённые артефакты (u8 флаг + `t_artifact_set`: u16 0, u16 число бит, биты). `d0c10` — u8 флаг + `t_bool_array` (u16 n, n байт; встретился один раз, n=312, смысл неизвестен). С v18 u8 флаг + набор навыков (`858150`: u8 0 + 5 байт). `d0f00` — u8 флаг + u16 число бит (≤188) + биты заклинаний. `d1370` с v24 ничего не читает (сцены теперь в заголовке). С v22 два `t_artifact_set` (`551330`). С v23 три карты важности для ИИ (артефакты `147f30`, заклинания `45ea60` дважды): u16 0, u16 n, n × (u16 id, u8 важность 1..2).
5. Объекты (`cf010`): u32 число; объект = i32 x, i32 y, i32 уровень, u8 «армия». Армия → `t_army::read_from_map` (`523a10`). Иначе строка модели (`adv_object.<модель>`), `t_qualified_adv_object_type` (`465960`: u16 0 и три пары u16 id + строка: тип, подтип, под-подтип) и тело объекта — виртуальный `read_from_map` (слот 36 vtable класса).

С этими пятью частями поток читается подряд: на всех 106 картах объекты кончаются ровно там, где поиск с конца находит начало тайлов (`tests/maps.rs`). Поиск остался в `map.rs` как запасной путь, если объекты не прочитались.

## Скрипты

Узел скрипта начинается со **строки типа**; игра ищет её в таблице и вызывает `read` класса. Три фабрики:

- действия (`10790`, 54 имени по таблице `41bb00`: `build`, `combat`, `if`, `seq`, `text`, `give_creature`, `set_num`, `gosub`…); класс — `t_script_action<N>`, read — слот 4 vtable;
- числовые выражения (`112d0`, 21 имя по `428010`: `lit`, `var`, `+`, `rand`, `day`…), read — слот 9;
- логические (`115f0`, 24 имени по `4286c0`: `and`, `==`, `is_dead`, `owns_town`, `true`…), read — слот 9.

Скрипт события — u16 версия (2) + действие; версия передаётся вниз и важна только для `text` (с v1 после текста — `seq`). Поля каждого типа — `crates/h4-formats/src/map_script.rs`. Цели (`u8` перед полями) — номера из enum'ов `t_script_*_target`, их смысл не разбирался.

События: discrete (`705b20`) = скрипт + сообщение + 7 × i32 ресурсов; timed добавляет имя, u16 первый день, u16 повтор; у событий городов/героев/армий/гарнизонов (`7d32d0`, `7d3590`, `7d3830`, `7d3af0`) — ещё u8 маска игроков и u8 флаги. «Встроенных» событий 4 у городов и гарнизонов, 3 у героев и армий.

## Армии и герои

Армия (`640830`): u16 0, 7 слотов; слот — u8: 0xff пусто, 0 существа (`63dc20`: u16 версия ≤1, i16 тип, i16 число, с v1 список артефактов), 1 герой. Артефакт (`664410`): u16 тип < 249, у типов 0x7c и 0xa6 ещё u16 заклинание.

Герой (`72f470`, версии 8–10): i16 портрет (−1 случайный), u8 класс, u8 пол, u8 и ещё 4 байта (до v10 — u8, 2×u16, 2×u8), имя, биография, u8 флаг + 36 × i8 навыков, набор заклинаний (`865e40`: u8 версия, 23 байта для v0, 24 для v1–2), 14 слотов экипировки (u8 + артефакт), рюкзак, 3 встроенных события и три списка событий, с v9 u8. Порядок байт после пола выведен по данным (декомпилят здесь путает читаемые байты), остальное — по коду.

Армия на карте (`523a10`, v9 у всех): u8 владелец, армия, патруль (v≥5: u8 флаг + 2 байта), события (3 встроенных + списки), три u8.

## Тела объектов

Тип объекта хранится **именем**; числа рядом с именами — из старого enum и с нынешним не совпадают (у `decorative` и `creature_bank` оба 20), поэтому разбираем по имени. Класс — по регистрации фабрик `t_object_factory<T>` (`k_registration$init` в каждом .cpp: `push factory; push тип; call 7c7dd0`). Таблицы ниже — в `map_body.rs`.

- Базовый `t_adventure_object::read_from_map` (`fab60`): только u16 0 — декорации, мосты, `system_object`, сокровища, ресурсы, святилища без настроек и ещё ~60 типов.
- `7232b0` / `t_adv_sign` (версия ≤1, в v1 строка): ворота, телепорты, паромы, водовороты, знаки, бутылки, ящик Пандоры, `event_trigger`, `deletion_marker`.
- `t_owned_scriptable_adv_object` (`7d7550`; версия ≤2: с v1 u8 владелец, с v2 список triggerable-событий): жилища, маяки, верфи, мельницы, еженедельные генераторы.
- Шахты и гарнизоны (`7d42b0`, ≤2): владелец, (не 6) u8, 4 встроенных события, continuous/timed/triggerable, u8 флаг + армия.
- Город (`89a8d0`, v4): два набора заклинаний и `read_map_data` (`417640`, v6–8): u8 владелец (цвет игрока, 6 — никто; у всех 659 городов установки это 6 или цвет игрока карты, фракция города — в модели), имя, u8 флаг + гарнизон, u8 флаг + 2×6 байт построек (иначе u8), 4 встроенных события, timed/triggerable/continuous, с v7 u8 флаг + 2 набора навыков, с v8 u8. Случайный город (`7f5220`, v7): «вид случайности» (`75c950`: u16 0 + строка `none`/`player` (+u8)/`town` (+строка)) и то же `read_map_data`.
- Прочие (`25db0` заброшенная шахта, `36f90` консерватория, `3c6d30` метка обелиска, `4a1440` аванпост, `67aa0` тюрьма с героем, `3eec0`/`37910`/`7f36a0`/`6cb80`/`2def0`/`73630` случайные объекты, `6c050` святилище, `41a1a0`/`18bd90`/`4cb770`/`366b00` школы и учителя — 2 набора навыков, `7ed940` квесты, `5bf0a0` переходящий герой, `430820` свиток) — в коде с комментариями.

Позиция объекта: x — наш ряд (`row`), y — столбец (`col`), как и оси футпринта в `adv_object`. Проверено по всем картам установки: так 77% декораций `*.Sand.*` стоят на песке и мосты в основном над водой, а при x = столбец — 27% и мосты над травой (первая версия была перепутана). С игрой попиксельно не сверено. Некоторые объекты у края стоят на −2…size.

## Ромб тайлов

`t_isometric_map_base_base::base_initialize` (rva `34db60`): карта size×size хранится рядами, ряд r — столбцы `[start, end)`. Верхний и нижний ряды — по 2 тайла, средние — полные (для 76: ряд 0 = 37..39, ряды 37–38 = 0..76, всего 2964 тайла на уровень). На экране этот ромб в изометрии даёт прямоугольник (подтверждено отрисовкой). Вершины (`t_isometric_vertex_map_base::initialize`, `34de80`) — size+1 рядов, каждый охватывает углы соседних рядов тайлов (+1).

## Тайл

Версия формата тайла зависит от версии карты (`FUN_004cad60`): >25 → 4, >18 → 3, ≥8 → 2, 6–7 → 1. В установке только 4.

```
u8 terrain (0..18), u8 subtype (< число подтипов: 2 у 0..8, 1 у 9..18)
u8 road (0..3)
u8 rock_terrain (0..2), u8 rock_transition (bool)    // версия ≥1
u32 visibility (версия 4) | u16 (версия 3: 6 полей по 2 бита → 3 бита, | 0x80000)
u8 n, n × { u8 terrain, u8 subtype, u16 id (9 бит), u8 mask_set (5 бит) }    // terrain transitions
u8 m, m × { u8 road, u16 id (9 бит), u8 mask_set (5 бит) }                   // road transitions
```

Имена полей — из геттеров `t_abstract_tile` / `t_terrain_transition` / `t_road_transition` в мапе (`get_road_type`, `get_rock_terrain_type`, `has_rock_terrain_transition`, `get_visibility`, `get_id`, `get_mask_set`). В памяти тайл упакован в u32: terrain 5 бит, subtype 1, road 2, rock 2, флаг 1, visibility выше.

- Enum земли (таблица rva `5958d8`): water, grass, rough, swamp, volcanic, snow, sand, dirt, subterranean, river, lava, ice, special_all/life/order/death/chaos/nature/combat. river/lava/ice — это реки (`terrain.river.water|lava|ice.*`), special_* — магические земли (`terrain.magic.*`).
- **Переходы сохранены в карте** (их считает редактор): id ≤ 92 — индекс маски в наборе в порядке файла, mask_set 0–19 — номер в таблице exe `6877a0`, 20 слотов на 4 имени наборов (см. `terrain_draw.md`).
- visibility: у всех тайлов всех карт биты выше 17 равны ровно 0x80000. На этом построена проверка, которая убирает ложные стартовые смещения у 3 карт. Гипотеза: 6 игроков × 3 бита видимости.
- Дороги: 1 — gravel, 2 — dirt, 3 — cobblestone (порядок массива текстур дорог в exe, rva `58ca68`; см. `terrain_draw.md`).

## Проверено

- 106/106 карт: заголовок, события, объекты, тайлы и высоты читаются подряд ровно до конца потока; конец объектов совпадает с началом тайлов, найденным поиском с конца.
- Смысл: все модели объектов существуют в архивах, позиции объектов внутри карты (с запасом в пару клеток у края).
- Смысл: подземный уровень почти везде subterranean/dirt, имена и описания — осмысленный русский текст, тексты победы и поражения стоят на своих местах, размеры совпадают с ожидаемыми 76/152/228/304.
- Отрисовка в `h4-game` (`H4_MAP=…`): реки, дороги и области земли складываются в цельную карту. С оригиналом попиксельно не сверено.

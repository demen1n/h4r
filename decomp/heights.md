# Высоты земли: освещение и подъём

Источник: декомпилят нашего `heroes4.exe` (сырой вывод — `light_raw.c`, `light_edge.c`, `light_apply.c`, `light_tile.c`, `light_read.c`), имена — из отладочного мапа (`abstract_adventure_map.obj`, `abstract_tile.obj`, `draw_adventure_tile.obj`). x87-места сверены по дизассемблеру.

## Данные

- `t_adventure_map::read_heights` (rva `cf4b0`): байт на вершину, без масштаба, в `t_isometric_vertex_map<int>`, затем `apply_height_map`.
- Вершина (`t_abstract_tile_vertex`): u16 высота (+0), u16 свет (+2).
- На 106 картах установки: 63 % вершин — 0, максимум 255. Разница соседних вершин по столбцу ≤ 16 почти везде (2 случая по 22): редактор ограничивает крутизну.

## Свет вершины

`t_abstract_adventure_map::apply_height_map` (rva `5b40`) пишет высоты, потом для каждой вершины свет = `compute_vertex_light` (rva `6820`). Он смотрит только на соседей **по той же строке** вершин (столбцы ±1):

- середина строки: `(edge(h[c−1], h[c]) + edge(h[c], h[c+1])) / 2`;
- первая вершина строки: `edge(h[c], h[c+1])`, последняя: `edge(h[c−1], h[c])`.

`compute_edge_light(a, b)` (rva `14230`), в 1/32768:

```
θ = atan2(a − b, 64/√2)            // a — вершина с меньшим столбцом
x = θ + 3π/4;  if x > π: x = 2π − x
x = x − π/2                         // = π/2 − |θ − π/4|
light = x <= 0 ? 0x1555 : 0x1555 + round(x · 54614 / (π/2))
```

Ровная земля — 32768 (×1.0), минимум 5461 (×1/6), максимум 60075 (×1.83) у склона 45°, который **опускается в сторону больших столбцов**, то есть смотрит на экране вниз-вправо: свет падает справа спереди (тени объектов в игре тоже ложатся влево). При предельной крутизне 16 на шаг: θ ≈ ±19.5°, свет ×1.36 / ×0.64.

## Применение к пикселю

`do_apply_lighting(цвет565, свет, bool, bool)` (rva `309520`, вызывается через `309500`): уровень `(свет + 256) >> 11` (0..32, 16 = ×1.0); цвет умножается на `уровень/16` сдвигами (`light_half/4th/8th/16th`), выше 16 — с насыщением по каналам (маски переполнения). Дробная четверть `(свет + 256) >> 9 & 3` добавляет 1 к уровню по шахматке 2×2 от чётности x, y пикселя: 1 — если обе нечётные, 2 — если x+y нечётно, 3 — если не обе чётные.

Как свет четырёх углов растягивается по тайлу, не разобрано (видимо, линейно, как геометрия ниже; рисует большой `307790`, куда всё встроено).

## Подъём земли

Игра **поднимает землю по высотам**. `shade_adventure_tile_helper` (rva `309070`) получает `t_quad<int>` высот углов и считает экранные y углов как `y − h + {16, 0, 16, 32}` (левый, верхний, правый, нижний). Каждый столбец пикселей левой половины тянется между рёбрами левый→верхний и левый→нижний, правой — верхний→правый и нижний→правый. Это аффинное отображение двух треугольников ромба, разрезанного по вертикальной диагонали (верх—низ): тайл можно рисовать как два текстурированных треугольника с поднятыми вершинами. Высота 1 = 1 пиксель вверх.

## Высота объектов

Сырой вывод — `height_obj.c`, `height_obj2.c`.

- `t_abstract_adventure_map::compute_height` (rva `7940`): высота объекта — округлённое среднее `(n/2 + сумма) / n` высот земли по вершинам футпринта (`(w+1)×(h+1)`, только существующие вершины). Если у модели есть флаг (vtable +4), считаются только вершины клеток, для которых модель отвечает «да» (vtable +0x14) — что это за клетки, не выяснено.
- `t_adventure_map::compute_height` (rva `d64f0`): для объектов, которые «используют высоты мостов» (vtable +0x74), на клетке-мосте — то же среднее, но по «высоте моста» вершины (третий u16 вершины, +4); иначе — как выше.
- `stamp_object_height` (rva `d6670`): высоты вершин модели (`adv_object`, если хоть одна не 0) пишутся **не в землю**, а в «высоту моста» вершины: `max(было, высота модели + высота объекта)`. Значит, высоты в файле карты — только земля, горы в них не добавлены.
- `get_object_height` (rva `5e10`) отдаёт сохранённую высоту объекта.

В прототипе (`h4-game/src/relief.rs`): земля поднимается при запекании (`Relief::raise`, по столбцам от дальних тайлов к ближним), объекты — на `object_height` по всем вершинам футпринта, армии — на высоту земли под ногами (интерполяция по двум треугольникам тайла, плавно при ходьбе), подсветка тайлов и выбор тайла мышью — по поднятым ромбам. Порядок отрисовки по глубине считается по плоским координатам.

## Не разобрано

- Флаг «только некоторые клетки» в `compute_height` и мосты (высота моста, `uses_bridge_heights`).
- На сколько игра поднимает армии (по клетке или плавно при ходьбе) и сортирует ли по глубине с учётом высоты.
- Интерполяция света внутри тайла.

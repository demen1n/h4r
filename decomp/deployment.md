# Начальная расстановка обычного боя (#57)

Источник — локальный русский exe 3.0 (Бука), адреса ниже — RVA.
Порт: `h4-rules/src/battle/deployment.rs`, API `BattleState::deploy_initial`.

## Координаты, стороны, размеры

`22d4b0` получает строй каждой армии из `t_creature_array + 0x2c`, затем вызывает
`22da90` сначала со стороной 0 (атакующий), затем 1 (защитник). Слот обходится в
исходном порядке 0..6; пустые слоты не уплотняются. Перед этим ИИ может переставить
и разделить стеки (`22d610`); это отдельная подготовка армии, в порт не входит.

`224270` инициализирует массив точек VA `aaf1e0`. Индекс точки:
`(formation * 2 + side) * 7 + slot`. Строи 0/1/2 — свободный/плотный/квадратный.
Точки — **якоря**, не левый верхний угол. `22dbb6..22dc24` вычисляет:

```
top_left = anchor - (diameter - 1) / 2   // по обеим координатам
native_position = top_left * 16        // субклетки
```

Чётный диаметр не округляется вверх. Координаты якорей сохранены в `STARTS` порта.
Они также участвуют в очистке зон старта от препятствий (`209190`).

Описание issue «1×1/2×2» не соответствует сетке оригинала: реальные модели существ
имеют диаметры **3–7 мелких клеток**. Например, mage — 4, behemoth — 6, black dragon — 7.
Размер задаётся первым байтом после версии `combat_actor` (`1deb50` записывает его в
`model+0x18`). Виртуальный геттер размера актёра `1d5120` читает модель через `1d7090`.
`CombatActorModel::footprint_size()` возвращает этот байт; для героев действует тот же путь.

Маска округлая, как у прочих `CombatFootprint` (`1fc340`); с размера 5 углы вырезаны.
Поэтому состояние боя больше не ограничивает `UnitPosition.size` числами 1 и 2.
JSON-схема прежняя; расширены проверки размеров и событий размещения. Ноль запрещён.

## Сжатие строя

После установки всех участников стороны `22da90` вызывает `22e3b0`:

- свободный строй не сжимается;
- плотный: попеременно 2 → 4 и 4 → 2 с лимитом 1, пока очередной сдвиг не удался;
  затем 0 → 2, 6 → 4, 1 → 3, 5 → 3 с лимитом 100;
- квадратный: 2 → 3, 0 → 2, 4 → 2, 1 → 3, 5 → 3, 6 → 3, 0 → 1, 4 → 5
  с лимитом 100.

Отсутствующий участник прекращает соответствующую попытку. Порядок и короткое
замыкание важны; аргументы вызовов проверены по дизассемблеру, поскольку Ghidra
в некоторых вызовах теряет третий/четвёртый аргумент.

`22e3b0` сравнивает центры футпринтов в субклетках (`position + size * 8`),
делит разность на 16 **к нулю**, затем берёт знак каждой координаты. По этому
фиксированному вектору проверяет очередной футпринт (`1651e0`) до блокировки или
исчерпания лимита. Проверок — максимум `limit + 1`; итоговая точка на шаг раньше
последней пробы. При успешном сдвиге оригинал пересчитывает высоту и перемещает объект.
Порт меняет позицию/занятость и пишет событие, высота относится к будущему рендереру.

## Границы API

Поле должно быть подготовлено заранее: земля, препятствия и очищенные зоны старта.
Порт проверяет **начальное** размещение и при блокировке отвергает операцию целиком.
Оригинал устанавливает начальный объект без этой проверки; воспроизводить наложение
стеков на блокирующие препятствия в валидируемом `BattleState` не стали.
Перерасстановка разрешена до первого раунда и атомарно заменяет прежние позиции.
RNG, численность, характеристики, исходные армии и их движение не меняются.

Не подключены контекстные переопределения `22d4b0`: мост (строй 5 для обеих сторон),
осада (3/4 для защитника), башни и поправки к позиции при осаде в `22da90`.
Они требуют соответствующего контекста поля, которого ещё нет в конструкторе боя.
Это не интеграция в `h4-game`: до #75 карта по-прежнему использует бой-заглушку.

## Сверка

```sh
.venv/bin/python tools/testbench/deployment.py --exe bin/heroes4.exe \
  --out /tmp/deployment_vectors.tsv
cargo test -p h4-rules --test deployment --locked
```

Стенд исполняет **оригинальные** `224270`, координатный блок `22dbb6..22dc07`,
маски `1fc340`, блок порядка сжатия `22dfbc..22e0cb` и полный помощник `22e3b0`. Входы виртуального размера,
проверка занятости, высота и запись позиции — границы фикстуры; занятость использует
маски, полученные от exe, и явные клетки препятствий. Последовательность вызовов
сжатия и короткое замыкание исполняются непосредственно из exe; полный `22da90`,
загрузка моделей и конструкторы боевых существ здесь не исполняются. Проходимость и маски отдельно сверены в #54.

156 сценариев: три строя, обе стороны, диаметры 1..7, смешанные размеры, пустые
слоты, отдельные участники, пары центральных слотов, препятствие на пути сжатия.
Эталоны хранятся в `tests/deployment_vectors.tsv` и работают в CI без игровых данных.
Если препятствие пересекает исходный футпринт, Rust ожидаемо отвергает всю расстановку;
остальные сценарии сравнивают окончательные позиции каждого слота и JSON round-trip.
Отдельные тесты проверяют атомарность, неверные размеры/ID, запрет после начала раунда
и сохранность исходных армий. Визуальная сверка с запущенным оригиналом не проводилась.

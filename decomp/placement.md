# Случайные объекты карты при старте игры

Код: `crates/h4-rules/src/placement.rs`, прогон по всем картам — `tests/placement.rs`, распечатка одной карты — `cargo run --release -p h4-rules --example place_map -- <map.h4c> [seed] [сложность]`. Адреса — rva нашего exe, если не сказано «VA».

## Стеки с числом 0 (ещё при чтении карты)

`t_creature::read` (`63dc20`) при числе 0 вызывает `7f4500(уровень существа)`: сила = `rand % (max − min + 1) + min`, min/max — те же 0.8 и 1.2 силы уровня, что у монстров (верх считается как `ftol(база × −1.2)` со сменой знака; поправки на сложность нет). Затем `n = сила × 256 / опыт`, не меньше 256; число существ — `n >> 8`, остаток хранится в `+0xa4` как доля 1/256 (у нас отброшен). Броски идут во время чтения объектов, раньше всех проходов ниже, в порядке файла: армии и гарнизоны (у гарнизонов бросаем, но результат пока не храним). Подсказку дал swift-ремейк (у них `0x63e1d7` английского exe), проверено по нашему коду.

## Порядок (`t_adventure_map::read_from_map`, `d15c0`, после тайлов и высот)

1. По всем объектам в порядке файла — `preplacement(map, 0)` (слот 29 vtable). Кто вернул true, откладывается.
2. Отложенные — `preplacement(map, pass)` с pass = 1, 2, … пока список не опустеет.
3. По всем объектам — `place(map, point)` (слот 28): случайный объект создаёт настоящий на своём месте.

Слоты найдены по vftable классов через RTTI (слот 36 — `read_from_map`, сходится с уже известными адресами). Имена tier D в переносе путают `place`/`preplacement` (у `t_random_adv_shrine` «place» `6cc40` на деле `preplacement`).

## Привязка (`75c950`)

«Вид случайности» из карты (`none` / `player` + цвет / `town` + имя) → число: 0..5 — фракция (тип города: haven, academy, necropolis, asylum, preserve, stronghold), 6 — любая, 7 — «потом». `player` — фракция игрока (`+0x60` игрока); нет игрока → 6. `town` — на проходе 0 всегда 7, дальше тип города с этим именем (`+0x118`), не нашёлся → 6. Перевод в тип города (`35c6b0`) — тождественный, 6 и 7 → −1.

## Правила

- **Город** (`3f5310`): тип по привязке; при 6/7 — тип города владельца, а у ничейного `rand % 6`. Модель — таблица VA `0xa5b6c8`: `castle.<тип>.<village|fort|citadel|castle>[ R]`, сторона R — подтип `right`. Уровень у нас всегда `fort` (уровень зависит от построек, которые мы не читаем; все настоящие города в картах — форты). Потом вызывается `preplacement` созданного города — не разобрано.
- **Жилище** (`3f020`): привязка 7 → отложить. Иначе в цикле: случайное существо уровня `level_N` из пула (`3bac0`: существа с моделью жилища, кроме пирата 50, по уровню, в порядке id), пока не совпадёт фракция (если задана) и дополнение (у существа дополнения 1 считается 2) не станет ≤ уровня дополнения карты. Модель — `creature generators.` + имя из VA `0x9740d0`.
- **Учитель** (`t_random_altar`, `2e000`; «алтарь» в exe — учитель первичного навыка): набор навыков по привязке — фракция 0..4 → школа магии 4..8, might → навыки 0..3, любая → все 9, «потом» → отложить; пересечение с маской из карты (u16 после версии, по умолчанию 0x1ff); пустое → маска карты, снова пустое → набор привязки; `rand % число` выбирает навык по порядку битов. Модель (`2e240` → конструктор `t_adv_altar`, `2d070`) — `Scholars.<Tactician|Combat|Scout|Noble|Priest|Scholar|Lich|Sorcerer|Druid>` (VA `0x971d48`).
- **Шрайн, храм** (`6cc40`, `736b0`): привязка 0..4 — школа/фракция, 7 — отложить, иначе `rand % 5`. Шрайн при `place` ещё выбирает заклинание (`46aec0`) — не разобрано. Модели: `shrines.<Школа> <уровень>`, храмы `moral-luck boosters.Temple of <Light|Order|Darkness|Chaos|Nature>` (сопоставлено по именам).
- **Куча ресурсов** (`3920a0`, конструктор `391380`): ресурс `rand % 7`; количество: золото `(rand % 5 + 4) * 100`, дерево и руда `rand % 5 + 4`, остальное `rand % 3 + 2`. Модель — VA `0xa737b4`.
- **Еженедельный генератор** (`4ccf30`, конструктор `4cbc20`): ресурс `rand % 6 + 1`, потом ещё бросок: при чётном генератор даёт 500 золота (модель остаётся от первого выбора). Иначе количество из VA `0x997ff0` (10 дерева/руды, 5 остального).
- **Артефакты** (`h4-rules/src/artifacts.rs`): `random_artifact` — по уровню (`4d9920`; подтип item/treasure/minor/major и есть уровень 0..3), `random_potion` — слот 17 любого уровня (`4d9f20`), `random_tome` / `random_staff` — из списков `[200, 202, 199, 198, 201]` / `[29, 182, 181, 185, 184]` (`4d9c40`). Общая схема: считаем неиспользованных кандидатов (без отключённых, с дополнением ≤ карты); если ноль — снимаем «использован» с разрешённых (кроме свитка 166 и пергамента 124), если снова ноль — со всех; `rand % n` выбирает среди неиспользованных, выбранный помечается. Начальное «использован» = не разрешён картой (или таблицей по умолчанию) плюс 124 и 166 — это вывод: первый подсчёт смотрит только на «использован»; что ещё туда попадает (временно подмешиваемый набор `4e7dc0`, настоящие артефакты на карте), не разобрано.
  - Номера: enum из таблицы ключевых слов VA `0x97bdc8` (пары id, имя; хвост — уровни и слоты), свойства из `table.Artifacts` по ключевому слову (`14ffb0`): `+0x24` слот, `+0x2c` уровень, `+0x61` отключён (список VA `0x97c608`, 40 шт.), `+0x64` дополнение (232..247, VA `0x97c6a8`).
  - Модель (`2f340`): префикс папки (`artifacts.amulets.` … `artifacts.tomes-books-manuals.`) + имя из таблиц пар (id, имя) VA `0x972278`…`0xa4b1d8`. У артефактов Winds of War (232..247) имён в этом exe нет, их модели лежат в `updates.h4r` — сопоставлены по названиям.
- **Монстр** (`3f38a0`):
  - уровни: `random_monster` — `level_N` (N..N), `random_random_monster` — 0..5;
  - сила (опыт): свой диапазон карты, если минимум > 0 (`+0xa8`, `+0xa4`, в единицах опыта крестьянина id 47), иначе по уровню (`3f44c0`): база 155·2, 310·2.5, 620·3, 1240·4 (VA `0x99004c`, `0x990058`), от ×0.8 до ×1.2; `random_random_monster` — как уровень 3;
  - сила = `(rand % (max − min + 1) + min) × k` с усечением, k по сложности 0.6667, 1, 1.5, 2, 3 (VA `0x990028`);
  - существо (`3f3310`): все подходящие равновероятно (k-е подходящее берётся с вероятностью 1/k, по броску на каждое). Подходит: дополнение ≤ уровня карты, опыт ≤ силы, водное (38 русалка, 50 пират, 52 морской змей) ровно на воде, уровень в диапазоне, фракция при привязке. Никто не подошёл — монстр не ставится (и в игре тоже);
  - число: у морского змея и русалки `сила / опыт`, у остальных `⌈2·сила / (3·опыт)⌉`, не меньше 1;
  - остаток силы, если есть (кроме змея и русалки), идёт во второй стек (`3f3240`): уровень первого или на 1 ниже, опыт ≤ min(опыт первого, остаток), равный — только сам первый; фракция — предположительно первого существа (берётся виртуальным вызовом у стека, не проверено). Число = `остаток / опыт`;
  - вода (`5340`): тайл water или river; игра ещё считает его сушей, если переход суши покрывает больше 255 пикселей маски — у нас любой переход суши.

Числа с плавающей точкой: x87 в exe работает с точностью double (по умолчанию у MSVC), поэтому `f64` даёт те же значения (310 × 1.2 = 372, а не 371).

## Существа (`255390`)

Статы в памяти — массив по id (VA `0xab2858`, шаг 0xe0), заполняется из `table.creatures` по ключевому слову. `+0x40` уровень, `+0x44` фракция (столбец Alignment), `+0x70` прирост, `+0x74` опыт (столбец Experience), `+0xdc` дополнение: 1 у id 67..70 (VA `0x985550`), 2 у 71..73 (`0x985560`), иначе 0.

Уровень дополнения карты (`map + 0x20c`) — по смещениям это u16 заголовка после версии (с v28): 0 база, 1 Gathering Storm, 2 Winds of War (у карт WoW 2).

## Случайные герои

`t_hero::preplacement` (`330e90`, зовётся армией с владельцем) на проходе 0 всегда «потом», на проходе 1 — `derandomize(map, игрок)` (`3311f0`). Тот работает только у героя без портрета (`+0x6d4 < 0`):

- класс −1: с игроком — случайный из базовых классов (0..10) его фракции (`7374a0` — фракция класса, `+100` игрока), без игрока — `rand % 11`;
- пол −1: `rand % 2` (1 — мужчина);
- потом из «стандартных героев» этого класса и пола выбирается один (`rand % n`) и `initialize` (`331560`) берёт у него имя, портрет, класс и пол.

У нас: класс и пол как выше, один бросок за выбор стандартного героя (сам он не выбирается). Фракция игрока известна, только если заголовок разрешает ему один тип города, иначе берём путь «без игрока». Герой с портретом, но классом −1 (класс, видимо, из стандартного героя по портрету) не разобран и рисуется моделью по умолчанию.

# Состояние боя (#53)

`h4_rules::battle::BattleState` — самостоятельное состояние без графики и ссылок
на карту приключений. Конструктор копирует участников из двух `MapArmy`, сохраняя
ID армий, владельцев, пустые слоты и героев. Копии статов существ позволяют
использовать снимок в тесте без архивов игры и без внешней таблицы характеристик.
Исходные армии, их движение и остатки прироста не изменяются.

```rust,ignore
use h4_rules::battle::BattleState;
use h4_rules::battle::deployment::Formation;
use h4_rules::battle::initiative::InitiativeStats;

// attacker/defender: &MapArmy; creatures: &[CreatureStats].
// field: a prepared BattlefieldGrid, with terrain and scenery occupants.
let mut battle = BattleState::from_armies(attacker, defender, creatures, field, 1234)?;
let ids: Vec<_> = battle.units().iter().map(|unit| unit.id).collect();

// The example assumes exactly one member per army. Get each diameter from
// its CombatActorModel::footprint_size(), including heroes' models.
let sizes = [(ids[0], 4), (ids[1], 7)];
battle.deploy_initial([Formation::Loose, Formation::Square], &sizes)?;
let fixture = battle.to_json()?;
let mut restored = BattleState::from_json(&fixture)?;

// Explicit fixture stats; real callers supply effective speed and morale
// after resolving hero skills, artifacts, spells and morale immunities.
restored.begin_initiative_round(&[
    (ids[0], InitiativeStats { speed: 5, morale: 0 }),
    (ids[1], InitiativeStats { speed: 8, morale: 0 }),
])?;
let active = restored.begin_next_turn()?;
let roll = restored.roll(ids[0].0, ids[1].0, 0);
restored.finish_turn()?;
```

## Что хранится

- Поле: поверхности клеток, флаги и занятость разрешёнными сегментами препятствий.
  Изображения и имена ресурсов здесь не нужны: это модель коллизий, не сцена рендера.
- Участники: стабильный `UnitId`, сторона, исходный слот и тип участника. Стек хранит
  исходную и текущую численность, HP верхнего существа, оставшиеся выстрелы и статы.
  Герой сохраняется как `Hero`; его боевые HP и характеристики ещё не восстановлены.
- Размещение: до вызова `deploy` позиция отсутствует. Перестановка до начала первого
  раунда проверяет нативный округлый футпринт (реальные модели — диаметром 3–7 клеток), край поля, землю и других участников.
  Неудачная операция оставляет поле, позицию и журнал прежними.
- Очередь: номер раунда, ожидающие, активный и завершившие действие участники.
  `begin_initiative_round` выбирает по правилам оригинала: скорость, мораль,
  ожидание и последняя выбранная сторона; `wait` откладывает действие, `defend`
  завершает его в защитной стойке. `begin_round(&ids)` остаётся для явного порядка
  фикстур. Нельзя пропустить, продублировать или добавить неизвестного участника,
  начать ход поверх активного либо раунд до окончания предыдущего.
  Участник, погибший до своего хода, из очереди выбрасывается (`begin_next_turn`
  его пропускает); уже сходивший остаётся в списке завершивших до конца раунда.
- RNG: зерно, модуль ID, счётчики бросков и checkpoints. Последние нельзя отбросить:
  в оригинале они влияют на малые индексы (`decomp/random.md`). Счётчики записываются
  в отсортированный список, поэтому JSON стабилен независимо от порядка HashMap.
- Журнал: создание, размещение, начало раунда, начало/конец хода, броски с результатом.
  Ошибки операций не добавляют событий.

ID участников выделяются с 1, обходя уже занятые ID сегментов поля; модуль RNG
равен наибольшему ID участника + 1. Сторона без участников — ошибка. Это наша явная схема
идентичности, а не восстановленный алгоритм выделения ID оригинала. Два отдельных
боя могут иметь одинаковые ID; они не ссылаются друг на друга.

## Снимки и проверки

`to_json`/`from_json` сохраняют начальное состояние и состояние между операциями,
включая активный ход. Формат имеет собственную версию (`SNAPSHOT_VERSION = 2`)
и не совместим с сейвами оригинала; снимки v1 отклоняются. Загрузка проверяет версию, геометрию поля,
ссылки ID/слотов, численность/HP/выстрелы, соответствие позиций занятости клеток,
очередь и структуру RNG. Броски из журнала повторяются на новом генераторе с тем
же зерном: значения и итоговые счётчики/checkpoints должны совпасть с сохранёнными,
а номера раундов в журнале — идти подряд до текущего. Поэтому генератор боя
используется только через `BattleState::roll`.

`tests/battle_state.rs` проверяет самостоятельность копий, героев и пустые слоты,
размещение и его атомарность, очередь, сохранение ранений и продолжение после
загрузки с теми же RNG/событиями. `tests/combat_random_state.rs` отдельно проверяет
кэш малых индексов, стабильную сериализацию и отказ для повреждённых данных RNG.
Все эти проверки работают без ресурсов игры.

## Следующие задачи

Это состояние ещё не исполняет команды движения и атаки. `battle::fight` остаётся заглушкой
карты до #75. Расстановка обычного боя реализована в #57 (`decomp/deployment.md`); порядок инициативы,
ожидание и защита реализованы в #60 (`decomp/initiative.md`); поиск пути и передвижение — #62, применение урона — #68,
боевые характеристики героев — #71. Герой в состоянии не считается автоматически
проигравшим из-за отсутствия существ; исход боя здесь пока не определяется.

## Начальная расстановка (#57)

`BattleState::deploy_initial([Formation; 2], &[(UnitId, u8)])` расставляет обе стороны
по исходным слотам армии и сжимает плотный/квадратный строй по правилам exe.
Диаметры берёт вызывающий из боевых моделей через `CombatActorModel::footprint_size()`.
Отдельного списка «больших существ» нет; герои используют ту же схему.
Пустой слот остаётся пустым, герой или стек не переносится в первый свободный слот.

Операция возможна до первого раунда, в том числе поверх ручного размещения.
Заблокированная начальная клетка, отсутствующий/дублирующийся ID или нулевой размер —
ошибка без изменения позиций, поля, RNG и журнала. Оригинал может установить стек
поверх препятствия; здесь это намеренно ошибка подготовки поля. При сжатии проверяются
земля, препятствия и другие участники; размер и численность не меняются.

Это обычный бой на подготовленном поле. Контекстные переопределения расстановки на
мосту, размещение в башнях и поправки осады пока не подключены. Перестановка и деление
армии ИИ до создания боевых участников (`22d610`) также не входят в эту операцию.

## Инициатива и команды (#60)

`begin_initiative_round` требует входы для всех участников, включая героев и
погибших, и бросает мораль по боевому RNG в порядке списка. При равенстве
приоритета предпочитается сторона, противоположная последней выбранной; ожидание
обращает приоритет, поэтому среди ожидающих медленные действуют раньше быстрых.
`pending` в нативном режиме содержит доступных участников, а не отсортированный
прогноз: следующий выбирается динамически. Эффективную скорость можно обновить
через `set_turn_speed`, не перебрасывая мораль. Повторное ожидание — ошибка.

`is_defending` показывает стойку; `apply_defense_stance(id, defense, effect_1f)`
применяет её множитель к уже разрешённой защите. Стойка переживает границу раунда
и снимается при следующем выборе этого участника. До #68 этот множитель не
подключён к полной команде урона; до #75 `h4-game` продолжает использовать заглушку.
Подробности и границы разрешения морали/эффектов — `decomp/initiative.md`.

# h4r — реверс Heroes of Might and Magic IV

Открытая кроссплатформенная реимплементация движка «Героев 4» на Rust и исследование оригинала: форматы данных, структура `heroes4.exe`, утилиты. Ресурсы берутся из установленной игры. Сейчас это ранний прототип: форматы читаются, карта приключений показывается и частично играется (ходьба, заглушка боя, смена дней); полной партии пока нет.

Отвечать по-русски; код, комментарии и коммиты — по-английски.

## Окружение

Личное окружение (какая установка игры, где лежит, что в ней изменено) — в `CLAUDE.local.md`, он не в git. Дальше:

- `$G` — папка установленной игры (в ней `heroes4.exe` и `data/`).
- Python-скрипты совместимы с 3.9 (без `datetime.UTC` и `match`); запускать с `python3 -I`.
- Соседний репозиторий [`demen1n/h4-mp3dec-fast`](https://github.com/demen1n/h4-mp3dec-fast) — быстрый `Mp3dec.asi`, плюс там же копии `h4r_quiet.py`/`h4r_merge.py`. Здесь — их версии на общем модуле `tools/h4r.py`.

## Rust-движок (начало)

CI: `.github/workflows/ci.yml` — push/PR/ручной запуск, macOS/Linux/Windows, Rust 1.99.1, `cargo build --workspace --all-targets --locked`, `cargo test --workspace --locked -- --nocapture`. Отдельная задача `Clippy` (Linux): `cargo clippy --workspace --all-targets --locked -- -D warnings` — любое предупреждение валит проверку; правило, которое ухудшает код, отключаем точечно `#[allow(...)]` с объяснением. В `main` — только через PR после зелёного CI (защита ветки). `H4_DATA` принудительно указывает на отсутствующий каталог; проверки оригинальных данных пропускаются с сообщениями. CI не проверяет графический запуск или совместимость ресурсов.

Собственный код и документация — GPL-3.0-or-later (решение 31 октября 2026; сначала было `-only`, сменили до публикации — как у соседних движков); полный текст `LICENSE`, область действия и происхождение `LICENSING.md`, зависимости `THIRD_PARTY.md`. Метаданные всех крейтов наследуют лицензию workspace. Чужой код автоматически не перелицензируется.

Цель — открытый кроссплатформенный (Mac/Windows/Linux) движок. Пользователь не силён в программировании и учит Rust на этом проекте: код пишем понятным, с комментариями «зачем», без хитрых трюков; объяснять решения.

Workspace в корне (`Cargo.toml`), Rust 1.99:
- `crates/h4-formats` — чтение данных без графики: `archive` (`.h4r`, порядок загрузки, алиасы, чтение по требованию — `heroes4.h4r` 677 МБ), `sprite` (слой, группа слоёв, `ActorSequence` v0–v3), `adv_object` (модели объектов карты), `catalog` (актёры → действия → направления), `png` (запись RGBA). `examples/check_sequences.rs` — разбор всех 13 336 анимаций (сейчас 0 ошибок).
- `crates/h4-state` — модель состояния, только данные (Serde для снимков идентификаторов армий и героев): `GameState` (версия `VERSION`, день, текущий игрок, игроки, карта, объекты, армии; `ArmyId` не переиспользуются), `map` (`AdventureMap`: тайлы по уровням — terrain id игры, дорога, `blocked` объектом, `bridge`, `inside` ромба; `MapObject`), `army` (7 слотов: стек или герой; `MapArmy` с владельцем и позицией). Собирает её `h4_rules::new_game::from_map(map, placements, footprint)` — футпринты моделей отдаёт вызывающий (правила архивы не открывают). На картах установки: 108 армий в файлах пустые (7 пустых слотов, нейтральные, без событий) — в состояние не попадают; 54 армии стоят на непроходимой клетке объекта (скелет, камень, вход жилища) — причуды карт, тест их только считает (`h4-rules/tests/new_game.rs`).
- `crates/h4-rules` — правила без графики. `random` — оба генератора оригинала бит-в-бит (глобальный LCG как MSVC `rand`, засев `time()`; боевой — число по индексу из (id, id, назначение, счётчик), `decomp/random.md`), `damage` — урон по `decomp/damage.md` (бросок, модификаторы, пределы, журнал `DamageEvent`; удар целиком — `attack_hit` с `HitOptions`; взгляд медузы 0x42 `stone_gaze` — в `finalize_attack_damage`, но допустимость эффекта 0x98 и сопротивление пока передаёт вызывающий через `Ability42Target`), `creatures` — статы из `table.creatures` (читатель таблиц — `h4-formats/src/table.rs`, ресурс `table.creatures.h4d`), порядок id как в enum игры (`KEYWORDS`), фракция, опыт, дополнение; `placement` — во что превращаются случайные объекты карты при старте (города, монстры, жилища, кучи, генераторы, шрайны, храмы, учителя, артефакты, зелья, томы, посохи), класс и пол случайных героев, размер стеков с числом 0 — порядок бросков как в exe, `decomp/placement.md`; `artifacts` — enum артефактов (VA `0x97bdc8`), модели на карте, выбор случайного артефакта; `heroes` — базовые классы (VA `0x989440`: фракция, маг или нет — список VA `0x989a54`) и модель героя на карте `hero.<фракция>_<might|magic>_<male|female>` (rva `2ad50`, `737ca0`; пол 1 — мужской); `movement` — движение армий по `decomp/movement.md`: стоимость земли (VA `0x985378`), родная земля фракции −50 (не ниже 100), армия = худшее существо, затем минимум с героями (Поиск пути); шаг по дороге (если она и в исходной клетке) 100 грунт / 75 гравий и булыжник, мост 75, диагональ ×1.5; очки `min(Move·100·11/25 + 1200, 3000)`, герой 2256, остаток — у каждого слота свой (float), у армии — минимум; пока очки есть, шаг можно сделать всегда (забирает остаток). `find_path` — Дейкстра (порядок обхода и учёт дней игры не повторены), `move_army` — идёт до врага (`MoveEvent::Attack`), препятствия или конца очков. Корабли, навыки, артефакты, зоны монстров — нет. `battle` — **заглушка боя** для среза: без поля, ходы по скорости, удар по первому живому стеку врага, ответ на ближний удар, стрелки без штрафов; урон и кости — настоящие (`damage`, `CombatRandom`, зерно — `GlobalRandom::next`); опыт = опыт убитых, каждому герою победителя; проигравший убирается с карты с героями (`attack`). Герои не дерутся, уровни не растут — всё это ещё искать в exe. `turns` — `begin_game` (запас движения всем), `end_turn`: следующий живой игрок, после последнего — новый день (`decomp/turns.md`): движение заново (rva `250ca0`), нейтральные стеки растут на `min(count/10, недельный прирост)/7` в день с остатком в 1/256 (rva `23de10`, `growth_remainder` в `MapArmy`). Нейтрального хода, недель и месяцев, дохода нет; функции передачи хода в exe не найдены.
- `h4_rules::battle::state::BattleState` (#53) — отдельное владеющее состояние боя: создание из двух `MapArmy` и подготовленного `BattlefieldGrid`, стороны/слоты, стеки с HP верхнего существа и выстрелами, герои без выдуманных боевых статов, явные позиции 1×1/2×2, очередь с порядком от вызывающего, журнал. Версионированные JSON-снимки (`to_json`/`from_json`) содержат копии статов и весь `CombatRandom` (зерно, модуль, отсортированные счётчики и checkpoints, необходимые для native cache quirk); загрузка проверяет ссылки, HP, сетку и занятость. Начальные позиции (#57), инициатива (#60), применение урона (#68), боевые статы героев (#71) и подключение вместо `fight` (#75) — отдельно. Это фундамент состояния, не готовый бой; API и пример — `docs/battle_state.md`.

Клавиши: клик — идти/атаковать, Tab — следующая армия, Enter — конец хода, Space — к армии. - Стыковка земли на настоящих картах — как в игре (`h4-game/src/mosaic.rs`, `t_metatile_map` rva `395400`): блоки 4×4 тайла; зерно — u32 заголовка (`terrain_seed`); перемешивание рангов блоков (`396f10`: элементу i — `rand % i`), затем по блоку: метатайл (`.1`/`.2`) для каждого типа и подтипа земли (число подтипов VA `0x9709d8`), для трёх дорог, «вылет» 0–2 (`rand` через шаг, `% 3`); метатайл блока начинается за `4 − вылет` тайлов до блока; клетку рисуют свой блок и соседи с большим рангом, которые до неё дотягиваются, верхний с полным «окном» закрывает нижние. Подсказка openh4, порядок бросков проверен по нашему декомпиляту, с оригиналом визуально не сверено. На сгенерированной карте (найдено экспериментом, `examples/terrain_tiling.rs`): метатайлы кладутся каждые 5 тайлов по обеим осям, внахлёст; первое число в имени — набор (вид), второе — чередование шахматкой. Дыр нет, швов не видно. Дороги — так же (`terrain.road.<вид>.<1|2>`), прокладывать без диагоналей, иначе пунктир; отрезки тестовой дороги — буквой «Г» (поиск в ширину давал лесенку). Края дорог на сгенерированной карте — как их кладёт редактор (сверено с переходами, сохранёнными во всех 106 картах, >99%): клетка с дорогой обрезается маской `road 1|2` с кодом соседей без дороги, но из двух соседних углов с цифрой 3 остаётся один, случайный (3333 → 3030/0303, 3123 → 3120/0123); клетке без дороги достаются только углы с цифрой 3 от соседней дороги (3102 → 3000, 21 → ничего) — `road_cut_code`/`road_edge_code` в `terrain_view.rs`. Если целого кода в наборе нет, маски берутся по углам.
- `adv_actor.*` (`h4-formats/src/adv_actor.rs`, все 154 читаются): u16 3, u8 1, u16 prewalk/walk/postwalk length (шаг на клетку = 32), u16 число действий; действие = имя, u8 кадров/с, 8 имён последовательностей (ne,e,se,s,sw,w,nw,n); в конце offset и flag_offset (i32×2 каждый). Значения полей подтверждены именами методов из мапа (`get_frames_per_second`, `get_walk_length`, `get_flag_offset`). В `h4-game/src/mover.rs` движение по фазам prewalk → walk → postwalk **по тикам кадров**, как в игре: кадр длится `100·(1000/fps)/процент` мс (процент — настройка скорости, у своих армий по умолчанию 150, `H4_WALK_SPEED`), за кадр актёр прыгает на длину фазы / число кадров, postwalk покрывает ровно остаток; диагональный шаг = 48 (прямой 32). У всех героев walk 32 за 6 кадров при 10 fps: прямой шаг 0,4 с, диагональ 0,6 с при 150% — сверено с записью экрана оригинала (флаг героя по кадрам). Формула кадра — из заметок Swift-ремейка, в нашем декомпиляте не проверена. `examples/walk_speeds.rs` — длины и тайминг ходьбы моделей. В покое wait + изредка fidget.
- Привязка спрайта: i32×2 после слоёв `ActorSequence` (`offset`, у грифона −361,−347) переводят координаты слоёв в систему «ноги в (0,0)». У героев нет `wait`, бездействие — `stand`.
- `ActorSequence` = `t_image_sequence` (rva `349930`): u16 внешний (2 в файлах, 1 в объектах), u16 версия 0–3; у v3 ещё 3×u16 (режим, base frame, base shadow — игра пересчитывает их по именам слоёв), у v1 после offset строка. Слои `base frame`/`base shadow` (анимированные постройки) — в `ActorSequence::base`, рисуются под каждым кадром.
- `adv_object.*` (`h4-formats/src/adv_object.rs`, все 2487 читаются ровно до конца, `examples/check_adv_objects.rs`; подробности и rva — `decomp/adv_object.md`): u16 версия (6), u8 кадров/с, u16 флаг кромок, u16 w, h; биты непроходимости `w*h` (индекс `y*w+x`), кромки-триггеры, блокировка кромок, высоты вершин; тип (3× id + имя: `decorative/tree/autumn`); u8 режим плоских клеток; флаг + смещение флага; u8 overlay/underlay; картинка = u16 версия + `ActorSequence`; у overlay u32 n + n×i16 глубины 32-пиксельных столбцов. Привязка: (0,0) после offset — верхний угол первой клетки; ось x футпринта — экран вниз-влево (`row`), y — вниз-вправо (`col`). В `h4-game/src/object_view.rs` объекты стоят на карте (лес, горы, постройки у старта), непроходимые клетки блокируют путь, картинка режется на столбцы и сортируется вместе с героями; тени рисуются сразу после земли. `H4_FOOTPRINTS=1` — обвести клетки объектов.
- Путь к данным: аргумент → `$H4_DATA` → обёртка Sikarugir (`h4_formats::archive::data_dir`).
- Ошибки: всё, что зависит от файлов игры, возвращает `Result` (в библиотеках паник на плохих данных нет). `unwrap` не пишем; где неудача невозможна (инвариант нашего кода) — `expect("почему тут не может быть ошибки")`. В примерах и тестах `unwrap` допустим.

## Архивы .h4r

`"H4R\x05"`, u32 смещение каталога, gzip-блобы (заголовок с XFL/OS = `00 0b`). Каталог: u32 число записей; запись = u32 offset, csize, size, time; три строки с u16-длиной (имя, исходный путь, alias); u32 тип. Запись с alias своих данных не имеет.

Порядок загрузки `heroes4.exe` (lsof на работающей игре): `x2_override`, `updates`, `text`, `music`, `movies`, `x2`, `storm`, `heroes4`. Первый найденный ресурс выигрывает, поэтому подменять что-то удобно через `updates.h4r`. Строки exe упоминают ещё `new.h4r`, `storm_updates`, `x2_updates` (файлов нет) и `storm_override` (файл есть, но в lsof его не было — не проверено). `new_mod.h4r` из `h4.dll` этот exe не грузит.

В `$G/data` есть ещё `equi.h4r`, `equi_text.h4r`, `equi_music.h4r`, `equi_hd_16_9.h4r`, `res_mod.h4r` и `*.aop` — `heroes4.exe` их не открывает, видимо, это для `h4mod.exe` (Equilibris). `updates.h4r` кроме звуков содержит `table.combat_obstacles`, `table.combat_grid_colors`, `table.spell_artifact_costs`.

Что лежит где (по префиксу имени):

### Ресурс sound

19 байт заголовка: byte0 — формат (0 PCM, 1 MP3), byte3 — бит на сэмпл, byte4 — каналы, далее u32 частота; затем данные. Заклинания — PCM 16/8 бит моно 22050 Гц. MP3 декодируется через Miles `Mp3dec.asi`.

### table.*.h4d

u32 число строк; строка = u16 число ячеек + ячейки (u16 длина + cp1251). Первые 2 строки — шапка с объединёнными ячейками, данные с 3-й строки. Есть байты 0x98 (не определены в cp1251) — декодировать с `errors='replace'`.

Таблицы: `creatures` (80 строк: уровень, школа, HP, урон, атака, защита, движение, скорость, выстрелы, мана, прирост, цены, опыт, описания), `Spells` (197: уровень, цена, школа, сила, флаги целей/иммунитетов, AI-веса), `creature_abilities`, `skills`, `skill_weights`, `heroes`, `Artifacts`, `buildings`, `creature_banks`, `Adventure Object`, `combat_obstacles`, `random_names`, `Interface`.

Вывод: цифры (статы, цены, флаги) — в данных; в коде — формулы, особые заклинания и способности, ИИ, скрипты.

### Графика: t_bitmap_layer_24 (`tools/h4_sprite.py`)

Читатель — rva `195570` (`t_bitmap_layer_24::read`, найден по порядку линковки: после трёх `adjust_*` и хелпера `read` в `1954e0`; перенесённое имя на `1cf00` «t_actor_sequence_24::read» — ошибка, там STL-дерево). Слой:

### Земля: метатайлы `terrain.*` (`crates/h4-formats/src/terrain.rs`)

Все 61 файл читаются. Метатайл = 10×10 изометрических тайлов 64×32 с общей палитрой (BGR); тайл — 64 столбца высотой 1,1,3,3…31,31…1 по центру, данные столбца — чередование `skip` / `count + индексы`. Края метатайла рваные и угловые тайлы пустые: игра накладывает метатайлы друг на друга и смешивает масками `transition.Transitions` (не разобран). Варианты `<type>.1.1/1.2/2.1/2.2`; `magic.*` — маленькие. `examples/dump_terrain.rs` рисует все в PNG.

### Переходы: `transition.Transitions.h4d` (`h4-formats/src/transition.rs`)

u8 число наборов (15: `land 1–3`, `road 1–2`, `water 1–2`, `river 1–2`, `water_to_land 1–3`, `land_to_water 1–3`); набор = u16-строка имя, u32 число масок (93), маска = i32 код, u8 глубина (1 или 4 бита), данные 160/544 байт (по столбцам ромба, столбец добит до байта). Размеры из таблицы в exe `0x9978cc`, читатель маски — rva `4c4e00` (имя в мапе съехало).
Код = цифра на угол ромба: тысячи E, сотни S, десятки W, единицы N; 1 — с ребра перед углом (по часовой от N), 2 — с ребра после, 3 — с обоих, 4 — только диагональный сосед (`corner_code`). Проверено по покрытию масок.
Тип земли в игре — пара (тип, подтип), enum из exe (`0x5958d8`): water, grass, rough, swamp, volcanic, snow, sand, dirt, subterranean, river, lava, ice, special_*. Порядок обработки (`0x996828`): реки, затем 0..8, затем special — взят как приоритет наложения (выше рисуется поверх). Подтипов у 0..8 по 2.
В `h4-game/src/terrain_view.rs`: тайл собирается из 4 метатайлов, поверх — старшие соседи через маску (`land N`; суша над водой — 4-битные `land_to_water N`; подтипы воды — `water N`), вариант набора — хэш клетки (это для сгенерированной карты).
В картах переходы уже посчитаны редактором: в тайле список (terrain, subtype, id, mask_set) и для дорог (road, id, mask_set). `mask_set` 0–19 → имя набора по таблице exe `6877a0` (0–4 `water_to_land`, 5–9 `land_to_water`, 10–14 `road`, 15–19 `land`; `MAP_MASK_SETS`), `id` — индекс маски в порядке файла (`Transitions::map_mask`). Игра рисует: свою землю, затем переходы в сохранённом порядке; дорога: если у тайла её нет — чужие дороги через маски, если есть — своя дорога, переходы с road 0 вырезают её край, с другим типом — рисуют поверх. Подробно — `decomp/terrain_draw.md`, код — `TerrainView::build_map`.

Даже без привязки к нашему exe мап полезен как справочник: имена методов, сигнатуры, какие функции в каком .cpp (например `t_abstract_combat_creature::get_damage_low`, `get_damage_spell_value(t_battlefield&, bool, t_spell, int)` в `combat_creature.obj`).

## Ghidra

Установка: `brew install ghidra` (12.1.4, тянет openjdk@25 keg-only). Headless:

```sh
export JAVA_HOME="$(brew --prefix openjdk@25)/libexec/openjdk.jdk/Contents/Home" GHIDRA_HEADLESS_MAXMEM=8G
AH="$(brew --prefix ghidra)/libexec/support/analyzeHeadless"
"$AH" ghidra heroes4 -process heroes4.exe -noanalysis -readOnly -scriptPath tools/ghidra \
  -postScript Decompile.java "$PWD/decomp/out.c" <depth> <rva> [rva...]
```

- Проект `ghidra/heroes4.gpr`, программа `heroes4.exe` (копия exe в `bin/`). Автоанализ ~3 мин.
- Уже сделано: автоанализ → `PaddedFunctionStarts.java 4fc000` (+9047 функций; EH-funclet'ы начинаются ~`0x4fc000`) → `ExportFeatures.java` → `transfer_names.py` → `ApplyNames.java`. Итого ~55k функций, 5293 имени.
- `tools/transfer_names.py`: перенос имён complete-3.0 → наш exe по форме функций (размер, число инструкций, `ret N`): 2522 якоря + 1780 в полосах между ними из 4823, плюс 991 vftable по RTTI-имени. Проверка: виртуальные методы попадают в vftable своего класса/наследника (расхождения — формат имён анонимных неймспейсов). Цель `rus-3.0` заведена в клоне: `maps/rus-3.0/{target.json,names.tsv}`, `work/rus-3.0/features/`, `binaries/rus-3.0/`.
- Python для их тулз: `HOMM4_PYTHON=.venv/bin/python third_party/homm4-symbols/tools/py tools/<x>.py rus-3.0` (venv с pefile+capstone).
- `tools/ghidra/Decompile.java` — декомпиляция по rva с обходом вызываемых на заданную глубину.
- Декомпилят x87-кода (float, `__ftol`) местами теряет аргументы — смотреть дизассемблер.

Результаты: `decomp/damage.md` (+ `damage.c`) — формула урона; `decomp/random.md` — генераторы случайных чисел. `re/enum_creature_ability.tsv` — enum способностей, прочитан из таблицы ключевых слов exe (VA `0xa64160`, пары `{i32 значение; char* имя}`, значение — номер в enum без сдвига; прежняя версия читала со сдвигом и путала 18 имён).

Сверка с exe: `tools/testbench/compare.py` (Unicorn, нужен наш `heroes4.exe` по sha256; README там же) выполняет оригинальный x86-код функций RNG и урона и сравнивает с `h4-rules` через `examples/exe_reference.rs`. Ответы оригинала сохранены в `crates/h4-rules/tests/*_vectors.tsv`, обычные тесты проверяют их без exe и Unicorn (CI тоже). Сверено: глобальный и боевой RNG (включая причуду кэша при модуле id 1), броски, цепочка модификаторов (коэффициент в 53-битной точности x87 до `__ftol`), финализация с 0x42, связанные удары. Это сверка функций, не целого боя.

## Смежные проекты

Над «Героями IV» работают и другие — спасибо им: на их выводах удобно проверять свои. Локальные клоны лежат в `third_party/engines/` (`free-heroes4`, `hommiv-remake-macos`, `engine4heroes`; `third_party/` в `.gitignore`). Мы сверяем с ними выводы и берём подсказки адресов, **код оттуда не переносим**. Оценки ниже — на конец октября 2026; проекты активно развиваются.

- `Anbrose/hommiv-remake-macos` — Swift + Metal, широкий охват: города, бой со способностями и заклинаниями, ИИ, сейвы, кампании. Лицензии нет, поэтому код не используем — только подсказки адресов для собственной проверки (их адреса — от английского exe, у нас сдвинуты). Некоторые решения у нас другие: карту читаем подряд (у них — поиск записей), случайные объекты — по правилам exe, боевой генератор — индексный, как в оригинале. Их формула бродячего монстра совпала с нашей (`decomp/placement.md`). Подсказки на проверку: стеки армий с числом 0 (у них `0x63e1d7`: 0.8–1.2 × бюджет уровня / опыт), уровень города по битам построек (8 форт, 16 цитадель, 32 замок).
- `ihhub/engine4heroes` — C++, GPL-3.0-or-later, от участника fheroes2. Строится основа: окно, главное меню, кнопки, часть ресурсов; до карт, правил и боя проект пока не дошёл, так что пересечений с нами мало.
- `tallowmere/free-heroes4` (openh4) — C++23 + SDL3, GPL-3.0. Форматы, карта читается подряд (`formats/scenario`), модель состояния отдельно от правил (`model/`, `rules/`), экраны меню и карты; боя и ИИ пока нет. Использовали только для сверки выводов, без переноса кода. Совпало с нами: `random_altar` = случайный учитель с маской навыков; u16 заголовка после версии — издание карты (у нас `expansion`); формула бродячего монстра (⌈2·сила / 3·опыт⌉ + второй стек). **Подсказка**: u32 заголовка (у нас `unknown_b`) у них `terrain_seed` — зерно MSVC-LCG для мозаики земли (`model/terrain_mosaic.cpp`): блоки 4×4, каждому блоку ранг (перемешивание), вариант метатайла по типу земли, вариант дороги и «вылет» 0–2 (`rand` два шага сразу `% 3`); клетку рисует блок с наибольшим рангом, который до неё дотягивается. Проверено частично: слитая константа двух шагов LCG (`0x560397F7`, `0x1E278E7A`) и `% 3` есть в нашем exe в коде `t_metatile_map` (rva `3955c0`, рядом `t_static_vector<…t_tile_info,4>,4>`). Случайные объекты они засевают тем же `terrain_seed` (в exe глобальный генератор засевается `time()`, `decomp/random.md`).
- Прочее: `Phylante/heroes4-reverse` (Python 2020, распаковка .h4r и музыки), `AntonOzhigin/homm4-mac` (оригинал под Wine), `Metalhead33/Homm4-img2map` (пишет `.h4c` из картинки — можно сверить наше чтение).
- Для ориентира по срокам: VCMI (H3) ~15 лет, fheroes2 (H2) 10+ лет, OpenMW ~15 лет.
